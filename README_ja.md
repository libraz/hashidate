# aituber

[![License](https://img.shields.io/badge/license-Apache--2.0-blue)](LICENSE)
[![TypeScript](https://img.shields.io/badge/TypeScript-7-blue?logo=typescript)](https://www.typescriptlang.org/)

**aituber は AITuber のためのアバターランタイムです。ブラウザで描画したキャラクタを、ローカルの HTTP API 経由で、1 ターンずつ外部から動かします。** レンダラがキャラクタを持ち、呼び出し側が台本を持ちます。

エンジンはアバターのデータを一切持ちません。作者が何をどう名付けたか、衣装がどう組まれているか、目がどこまで動くか、どのシェイプが部品ではなく描き起こしの完成形なのか——特定のモデル固有の事情はすべて記述子に置き、ランタイムはプロファイル越しにそれを読みます。アバターを差し替えるとはこのオブジェクトを差し替えることであり、それ以外は変わりません。このリポジトリが検証しているのはその一点です。作者の異なる 2 体、片方は ARKit の 52 ブレンドシェイプに対応し、もう片方は 1 本も持たない——を、同じエンジンと同じコマンド語彙で動かします。

**こういうときに使います。**

- **LLM のループからキャラクタを動かす** — コマンド 1 つがターン 1 つ。台詞と表情とモーションを渡し、必要なら言い終わるまで待てます。
- **キャラクタの言葉で頼む** — 「joy 0.9 と cheer ジェスチャと 45mm の跳躍 3 回」ではなく「うれしい」。名前の付いたプリセットが語彙で、アイドル時の自動モードも同じ表から選びます。
- **エンジンに触らずアバターを替える** — アバター固有のファイルは記述子だけ。何を頼めるかは宣言ではなく、モデル自身のシェイプとメッシュから発見されます。
- **すべて手元のマシンで完結させる** — ビューアも制御 API もループバックにしか bind せず、ランタイムのどこにもクラウド依存はありません。

## 中身

- **プロファイルの発見** — ボーン、指の命名族、ビセーム、瞬きシェイプ、描き起こし表情のグループを、モデルが実際に持っているものから解決します。ARKit 対応は前提ではなく判定結果です。
- **プリセット** — 表情とモーションをひと組の名前にしたもの。何の類かでグループ分けし、状態として出入りします。この 1 枚の表を、制御 API も操作卓も自動モードも同じように話します。
- **モーション** — サッカードとばねで動く視線、呼吸と重心移動のアイドル、ジェスチャ表、跳躍、そして指先の位置から逆に解いた腕。関節の負担も返します。
- **表情** — ARKit かモデル自身のシェイプに合成される感情ブレンド、描き起こし表情、重ねる効果、瞼の伏せを持つ瞬きスケジューラ、テキスト起点のリップシンク。
- **揺れもの** — 髪と衣装のばねチェーン。コライダと尻尾つき。
- **衣装** — スロット、組み合わせのプリセット、それに伴う隠しシェイプ。モデルのメッシュから読み取ります。
- **制御 API** — SSE でコマンドを下ろし、状態とターンのイベントを上げます。語彙はシステムプロンプトに貼れる形で返ります。

## リポジトリの構成

| | |
|---|---|
| `src/engine` | ランタイム本体。プロファイル、リグ、可動域、モーション、表情、揺れもの、ディレクタ、セッション。three.js には依存しますが、ブラウザの API には依存しません。 |
| `src/avatars` | モデル 1 体につき記述子 1 ファイル。アバターを増やすとはファイルを増やすことです。 |
| `src/protocol` | 通信仕様を zod スキーマで定義したもの。ビューア・サーバ・CLI がこれを共有するので、コマンド語彙が三者でずれません。 |
| `src/viewer` | 操作卓。three.js のステージの横に React のパネルが並びます。 |
| `src/server` | ローカル制御 API。ビルド済みビューアの配信とコマンドの中継を兼ねます。 |
| `src/cli` | `ctl`。手で動かすための薄いクライアントです。 |
| `tools/blender` | モデル変換。Blender 組み込みの Python で動くため、ここだけ Python です。 |

## 必要なもの

- Node と Yarn。`mise.toml` で固定してあります（`mise install`）
- Blender。モデル変換にのみ使います
- アバターのパッケージ本体。市販品であり、**このリポジトリには含まれません**。[アセット](#アセット)を参照してください

## クイックスタート

```sh
yarn install
yarn dev
```

`yarn dev` はビューアを `127.0.0.1:5173` に、制御 API を `127.0.0.1:8765` に立て、前者の `/api` を後者へ中継します。別のターミナルから動かします。

```sh
yarn ctl vocab                                  # このアバターに何を頼めるか
yarn ctl perform happy                          # 表情とモーションをひと組にしたもの
yarn ctl say "こんばんは" --perform hello --wait
yarn ctl say "[hello]こんばんは。[explain]今日はこの話をします。"
yarn ctl perform                                # 解除する
yarn ctl point 40 25 --extent 0.9 --finger little
yarn ctl idle on
yarn ctl watch                                  # ターンのイベントを追う
```

`yarn build` は `dist/` に静的なビューアを吐きます。`yarn start` は vite を介さず、制御サーバ単体でそれを配信します。

実際に声を出したいときは、最初に一度 `make tts-setup`、あとは `make tts` を並走させます。本当の意味で任意です——[音声](#音声)を参照。

## 制御 API

オーケストレータ——本番では LLM のループ——がコマンドを投げ、状態を読みます。

```
オーケストレータ  ──POST /api/command──►  サーバ  ──SSE──►  ビューア
                  ◄──GET  /api/state───           ◄─POST──
```

作業の単位は**ターン**です。1 行の台詞を、表情とジェスチャを添えて届け、終わったら次へ進みます。`POST /api/command?wait=1` はターンが終わるまで返らないので、キャラクタが喋り終わるまで何もすることのない呼び出し側がポーリングを書かずに済みます。

### プリセット

台詞に添えるものは、たいていは**プリセット**——「うれしい」「ねおち」のように、表情とモーションをひと組の名前にしたものです。その下の層が分かれているのには理由があり（感情は連続値で持続する、ジェスチャは離散的で終わる、跳躍は骨格全体を動かす）、そのどれも呼び出し側が考える単位ではありません。

表はグループ分けしてあり、グループがそのまま「それが何の類か」を表します。気分（表情だけで、動かない。キャラクタを眺めている時間の大半は実際これです）、相槌、挨拶、説明、感情、仕草、そしてポーズ——ポーズは次に何か頼まれるまで保持されます。エンジンの持つジェスチャはすべてどれかのプリセットに現れ、それを保証するテストがあります。表情の付いていないモーションは、いずれ自動モードが無表情のまま再生してしまうものだからです。

プリセットはイベントではなく**状態**です。新しく始めると前のものが終わります——ポーズは降り、上げた効果は下がり、伏せた瞼は戻ります。例外は気分で、これだけは持続します。ターンの感情が持続するのと同じ理由で、気分はそれを乗せた文とともに終わるものではないからです。

プリセットに名前のない組み合わせのために、下の層はそのまま呼べるようにしてあります。アイドル時の自動モードも同じ表から選ぶので、キャラクタが勝手にやることと頼めることは同じ語彙になります。

### 原稿の中の演出

プリセットは普通ターン全体に掛かります。ターンの**途中**で変える必要があるときは、原稿にそのまま書きます。

```
[hello]こんばんは。[explain]今日はこの話をします。
```

角括弧に囲んだプリセット id は、書かれた位置でそのプリセットを始めます。文の途中に置く方法は他にありません。ターンを 2 つに割れば節の真ん中に間と息が入りますし、`perform` を別に投げても前半を言い終わる時刻は分かりません——それを知っているのはレンダラだけです。

**角括弧は予約されていて、その中身が読み上げられることはありません。**これはこの構文の細部ではなく、この形をしている理由そのものです。呼び出し側は言語モデルで、書いたものはすべて口へ行きます。キャラクタがト書きを音読するのがこの設計の避けたい失敗です。そこで二重に保証しています。解釈できない記法を含む行はスキーマを通らず、コマンドごと捨てられます——キャラクタは黙り、呼び出し側には伝わります。その後ろにいるパーサは全域関数で、別の経路からエンジンに届いた行も、読み上げられるのではなく記法が取り除かれた形で出てきます。解釈を切るフラグはなく、台詞が届きうる 2 つめのフィールドもありません。

演出の位置は時刻ではなく発話全体に対する割合で保持し、口自身の時計に乗せています。そのため見積もりより長く喋ることになっても、書かれた場所に留まります——`reading` を添えれば長さは変わりますし、TTS の音声はまた別の長さになるからです。プリセット表にない id は捨てられます。文の途中では、打ち間違いは何も起こさないのが正しく、キャラクタの顔を落とすのは正しくありません。

### 音声

`tools/tts/` のサイドカーが動いていれば、台詞は再生前に合成され、口は推定ではなく実音声で動きます。動いていなければ何も変わりません。テキストから組み立てた尺で無音のまま口だけが動く——声を持たない環境と、テストが走っている状態です。

**ターンが開く前に完成した音声が手元にある**ことから 3 つが導かれ、それが合成にかかる 1 秒に見合う理由です。

- **口形トラックを実尺へ引き伸ばす。** 推定の定数は比率を作るためだけに使われるので、実測長へ正規化すると定数が消えます。声を再学習して喋る速さが変わっても timing が生き残るのはこのためです。この環境では長い行で推定が 15% 短く、短い行ではもっと大きく外れます
- **口を音声の時計に乗せる。** フレームは落ちますが音声は落ちないので、フレーム差分を足し込む口は先走る方向にしかずれません。演出の cue も同じ時計を読むので、同じ 1 行で一緒に補正されます
- **口の開き量を、その take 自身の音量で決める。** デコード済みバッファから 1 度だけ測り、その take 自身の水準で正規化するので、声を替えるたびに調整するゲイン定数がありません。テキストが予測できなかった間で口を閉じるのはこれで、引き伸ばしでは直せない部分の大半を隠してくれます

合成が始まるのは台詞が**積まれた**時点であって再生される時点ではないので、3 行まとめて投げれば 3 本が同時に走り、待つのは連続した発話の最初の 1 ターンだけです。声が落ちたり応答しなくても、失うのはその行の音だけです。ターンは無音で再生され、キューは止まりません。

### コマンド

| | |
|---|---|
| `perform` | 表情とモーションをひと組にしたもの。id なしで、出ているものを解除します。 |
| `say` | ターンを積みます。`perform` を添えるか、部品を個別に指定するか、原稿の中に直接書きます。`hold` を付けると台詞が終わっても表情が残ります。表記から読みが決まらない場合は `reading` に仮名で渡します（こちらに演出は書けません）。 |
| `emotion` | 持続する気分。択一ではなくブレンドです。 |
| `expression` | アバター自身の描き起こし表情。`null` で感情ベクトルに顔を返します。 |
| `overlay` | 描き起こしの効果を、重みを付けて。出ている顔の上に重なるので、複数を同時に上げられます。 |
| `gesture` | ジェスチャ表から 1 つ。id なしで止まります。 |
| `hop` | 跳躍。骨格全体を平行移動させるためジェスチャとは別のコマンドで、腕が何をしていようと並行して走ります。 |
| `point` | 指先を方位に向けます。ワイヤ上は度で、5 本のどの指でも指せます。解除するまで保持されます。 |
| `look` | 視線がカメラを追う度合い。0 から 1。 |
| `idle` | 自動モードの入切。 |
| `camera` | 画角。`face` / `bust` / `upper` / `full`。 |
| `wear` | スロットに 1 着、またはプリセットで一式。 |
| `interrupt` / `clear` / `reset` | 台詞を切って積んだ分も捨てる / 積んだ分だけ捨てて今の台詞は言い切る / すべて初期状態へ。 |

レンダラが解釈できないコマンドは、リクエスト全体を失敗させずに捨てられます。知らないフィールドも同様に落とされます。オーケストレータとレンダラは別プロセスで、リリースの周期も別です。新しい呼び出し側が古いレンダラに話しかけたとき、ストリームごと壊れるよりは劣化して動き続けるほうが正しい。

### エンドポイント

| | |
|---|---|
| `POST /api/command` | コマンド 1 つ、または `batch` に並べてまとめて。`?wait=1` は最後に積んだターンが終わるまで返りません。 |
| `GET /api/state` | 接続状況・現在の状態・`?since=` 以降のイベント。 |
| `GET /api/events` | イベントだけ。`?wait=1` でロングポーリングになります。 |
| `GET /api/vocabulary` | 読み込み中のアバターに何を頼めるか。 |
| `GET /api/stream` | ビューアへの SSE 下り。 |
| `POST /api/report` | ビューアからの上り。ハートビートも兼ねます。呼び出し側が使うものではありません。 |
| `POST /api/speech` | ビューアから音声サイドカーへの経路。呼び出し側が使うものではありません。サイドカーが居なければ 503 で、それは正常な返事です。 |

`/api/speech` がビューアから `tools/tts/` を直接叩くのではなく中継なのは、ここが全部ループバックなのと同じ理由です。サイドカーは CORS ヘッダを出さないので、このオリジンのページからあちらへは届きません。直接叩けるようにする方法は「声側に CORS ヘッダを足す」か「声をループバックから出す」の 2 つだけで、どちらもライセンスの判断です。中継はそのどちらでもありません。

### 返ってくるもの

`GET /api/vocabulary` は、読み込み中のアバターに何を頼めるかを返します。これは宣言ではなく発見されたものです。表情の一覧はモデル自身のシェイプ群から、衣装はメッシュから引いているので、アバターが変われば中身も変わります。システムプロンプトに貼るのはこのオブジェクトです。原稿の記法もその中に入れてあるのは同じ理由で、伝えていない構文は誰にも使われないからです。

`GET /api/state` は分岐に使う値をひと通り、ポーリングに耐える軽さで返します。発話中かどうか、ターン id、積まれている数、感情ベクトル、出ている描き起こし表情と効果、保持中のプリセットとジェスチャ、そして `strain`——直前の指先解決が各腕にどれだけ無理をさせたかです。指さしの角度は、語彙が告げる範囲に**あえて**制限していません。あの範囲は解剖学的なもので、それを超えて手を伸ばすのはエラーではなく想定された結果です。腕は届く限りのところまで行きます。人がそうするからで、そして strain の値は、狙いどおりに届いたのか近似しかできなかったのかを呼び出し側が知る唯一の手段です。

## 操作卓

ステージの横のパネルはタブが 4 枚です。演じる（プリセット、感情、描き起こし表情、重ねる効果、ジェスチャ、指さし）、装う（衣装）、調律（アイドル、揺れもの、跳躍、描画）、診る（読み取り専用——関節の負担、解決済みのプロファイル、イベントログ、語彙）。アバターの選択・画角・アイドルの切替・台詞の入力欄はタブの外にあります。この 4 つのどれか 1 つに属するものではないからです。

パネルは制御 API と同じ `Session` を動かします。エンジンへの二本目の経路ではないので、API の検証にそのまま使えます。

## アセット

検証用の 2 体は市販の VRChat 向けモデルです。購入時のパッケージ、そこから取り出したメッシュとテクスチャ、ビューアが読む GLB——いずれも git 管理外にしてあります。合わせて 1.5 GB あり、そもそも再配布できるものではありません。

パイプラインは購入パッケージを GLB に変換します。

```sh
make            # 各ターゲットの説明
make extract    # 購入 zip      → backup/resource/
make textures   # unitypackage  → PNG
make resize     # 4K            → Web 用に縮小
make glb        # FBX           → public/models/*.glb
```

`make check-assets` は、1 MB を超えるファイルが git に紛れ込んでいれば失敗します。パスの一覧ではなく、git が実際に追跡している中身を測ります。`.gitignore` は誰かが思いついたパスしか守れませんし、500 MB の塊が履歴に 1 度入れば取り返しがつきません。

## 開発

```sh
yarn typecheck
yarn lint          # biome
yarn test          # vitest
```

テストは GLB を読まず、コード上で合成のアバターを組み立てます。購入した 16 MB のモデルを必要とするテストは、それを買ったマシンでしか走りません。`tests/helpers/scene.ts` を参照してください。

`src/engine` の数値は、実際のアバター 2 体を見ながら決めたものです。その多くには、何を防ぐために存在するのかを書いたコメントが付いています。整理のついでに丸めてよい既定値ではなく、変えるならレンダリングを見て判断することになります。

## やらないこと

aituber はキャラクタを描いて動かすものであって、AITuber そのものではありません。言語モデルも音声認識も配信の出力も含みませんし、何を喋るかを決めるオーケストレータはこのリポジトリの外にいます。

一線を越えたのは音声合成だけで、それも `tools/tts/` の範囲に留めてあります。台詞を音声に変えるサイドカーで、HTTP 越しに叩くだけで import はしません。エンジン自体も音声のコードは持たず、「喋られた台詞とは何か」を型で述べるだけで、`AudioContext` を持つビューアがそれを実装します。サイドカーが無ければ以前どおり動き、口はテキストから組み立てた尺で動きます。

ループバック限定であることも意図的です。`--host` フラグも CORS ヘッダもトンネルもありません。検証に使っているアバターは再配布が許されておらず、レンダラを外に出すのはコードの変更である前にライセンスの判断だからです。

エンジンはランタイムであってエディタではありません。リギング・ウェイト・衣装の作成は Blender の仕事で、`tools/blender` がその境目です。
