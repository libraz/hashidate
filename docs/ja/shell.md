# ネイティブシェル

```sh
yarn shell
```

ページをビルドし、制御サーバと、このチェックアウトに用意があれば音声サイドカーを起動し、パネルとステージをネイティブのウィンドウ 2 枚として開きます。終了すると、シェル自身が起動したものはすべて一緒に落ちます。

![`yarn shell` が起動するもの](../images/shell-ja.svg)

これは 4 つ目の操作面ではなく、便宜のための入れ物です。中で開いているのは同じループバックアドレスの同じ 3 ページですし、配信に対してできることも同じ制御 API を通ります。足しているのはブラウザのタブにはできないことだけで、そのどれもが番組ではなく卓についての問いです。

| 足しているもの | ブラウザにできない理由 |
|---|---|
| ウィンドウが前回置いた位置に戻る | タブには、どの画面のどこへ置いたかという記憶がありません |
| ステージがクリックなしで音を出しはじめる | 自動再生には操作が要りますが、オペレータがクリックすべきページがありません |
| `Window → Mute Stage` | **この機械**が音を出すかどうかは、番組の性質ではありません |
| 終了 1 回で 3 プロセスが止まる | ターミナルを閉じただけでは、サーバとサイドカーがアドレスを掴んだまま残ります |
| show 配下のディレクトリをファイルマネージャで開ける | ページからは、配信元の機械のパスを名指しできません |
| 台本をファイルダイアログから選べる | パネルは `show/scripts/` を一覧できますが、それ以外の場所のファイルは読めません |

## 何を起動するか

プロセスは 3 つで、順番も次のとおりです。

1. **制御サーバ**を `127.0.0.1:8765` に起動します。このチェックアウトの `dist/` と `show/` 配下のディレクトリを、コマンドラインで渡します。
2. **音声サイドカー**を起動します。ただし `tools/tts/.venv/bin/python` が存在し、かつソケットで誰も応答していない場合だけです。起動はしますが完了を待ちません。モデルの読み込みには 1 分近くかかりますし、ビューアと制御 API は声がなくても動くためです。
3. **ウィンドウ 2 枚**を `/panel/` と `/monitor/` に開きます。

**同じチェックアウトの制御サーバがすでに動いていれば、置き換えずにそれを使います。** ターミナルに立ち上げっぱなしの `yarn dev` を落とさないためです。終了時にもそれは止めません。シェルが止めるのは、自分で起動した子プロセスだけです。

**別の**チェックアウトのサーバだった場合は、黙って使わずに、名指しで拒否します。

```
:8765 is held by a control server for /Users/…/other/dist, but this checkout
serves /Users/…/hashidate/dist. Stop it, or start this one on another port
with HASHIDATE_CONTROL_PORT.
```

この確認があるのは、チェックアウトが 2 つあっても `/api/state` の答え方が同じだからです。間違ったほうを採用すると、オペレータの手元には他人のビルドから読み込まれたウィンドウが 2 枚並び、メニューは**こちらの**チェックアウトの show ディレクトリを開きながら、動かしているのは別のチェックアウト、という状態になります。しかもエラーはどこにも出ません。見た目はレンダラが立ち上がらない状態とまったく同じになります。

`yarn shell` を 2 回目に実行しても、アプリケーションが 2 つ立ち上がることはありません。すでに動いているほうのウィンドウを前に出します。順番はステージが先、パネルが後で、結果としてパネルにフォーカスが当たります。

## メニュー

| メニュー | 項目 | 何をするか |
|---|---|---|
| File | Run Script…（`⌘⇧O` / `Ctrl+Shift+O`） | ディスク上のどこからでも `.yaml`・`.yml`・`.json` の台本を選び、`yarn ctl play` と同じようにキューへ積みます |
| Edit | Undo, Redo, Cut, Copy, Paste, Select All | macOS は、これらのロールをメニューに持つウィンドウでしかショートカットを繋がないためです。パネルは台詞を書き込むページです |
| Window | hashidate — Control | パネルを前に出します。閉じてあれば開き直します |
| Window | hashidate — Stage | ステージを前に出します。閉じてあれば開き直します |
| Window | Mute Stage | ステージウィンドウを無音で開くかどうか。次回起動時にも引き継ぎます |
| Window | Open Slides / Scripts / Motions / BGM / Recordings Folder | show 配下のディレクトリをファイルマネージャで開きます |
| Window | 状態表示 3 行 | 読むだけの行です。次節を参照してください |

Window メニューの末尾にある 3 行は、`GET /api/state` から 2 秒ごとに更新されます。

| 行 | 取りうる値 |
|---|---|
| `● Control` | `starting`、`online`、`offline` |
| `● Speech` | `ready`、`loading`、`absent`、`down`、`unknown` |
| `● Renderers` | `connected (n)`、`disconnected` |

更新間隔をパネル自身のポーリングより遅くしてあるのは意図的です。ここは配信中に読む場所ではなく、すでに何かおかしいと感じたときにメニューを開いて見る 3 行だからです。`Renderers` が数えるのは接続中のレンダラすべてで、常に開いているステージウィンドウもその 1 つに含まれます。したがってこの数字は、OBS が本番に出ていることの証明にはなりません。制御プロトコル上、OBS には固有の見分けがつかないためです。

`Speech: absent` は、サイドカーが見つからなかったという意味です。`make voice` をまだ走らせていないチェックアウトでは、これが通常の状態です。対処が要るのは `down` のほうで、一度は応答していたサイドカーが止まったことを意味します。キューは流れ続け、口も動き続けるので、配信の途中で落ちた声はこれ以外の形では見えません。[音声](speech.md)を参照してください。

## Mute Stage

ステージウィンドウは、このアプリケーションの中で唯一音を出すレンダラです。音を出すべきかどうかは、卓の側の事情で決まります。

- OBS でブラウザソースを**モニタリングしている**場合、部屋はすでにキャラクターの声を聞いています。このウィンドウも鳴らすと、1 行がコンマ何秒ずれて二重に聞こえます。ミュートしてください。
- モニタリングを**していない**場合、部屋で声を聞く手段はこのウィンドウだけです。音を出したままにしてください。

この問いには、オーケストレータも台本の 1 行も答えられません。そのためスイッチにしてあり、次回の起動にも引き継ぎます。

代償として、切り替えには再読み込みが伴います。ミュートは、すでに開いているページへ送るのではなく URL（`/monitor/?mute=1`）に載せているためです。そのためモデルが読み込み直され、画は 1〜2 秒だけ黒くなります。この設定では妥当な代償で、パネルのプレビューでは妥当ではありません。ここは配信中に手を伸ばす操作ではなく、卓を組むときに一度決める設定だからです。[レンダラの URL](surfaces.md#レンダラの-url)を参照してください。

## 状態とログの置き場所

| 対象 | 置き場所 | 補足 |
|---|---|---|
| ウィンドウの位置とステージのミュート | Electron のプロファイルの隣の `shell-state.json` | macOS では `~/Library/Application Support/hashidate/`。現在どのディスプレイにも掛からない位置は、復元せずに捨てます |
| 制御サーバの出力 | Electron のログディレクトリの `control.log` | macOS では `~/Library/Logs/hashidate/`。追記なので、起動に失敗し続けた履歴も丸ごと残ります |
| サイドカーの出力 | その隣の `speech.log` | モデルの読み込みに失敗したときに、それが記録される場所です |

この 2 つのログが、音が出ない場合とレンダラが立ち上がらない場合の確認先になります。

## ウィンドウに許していること

シェルは、アドレスバーを取り上げたブラウザです。そのため、ブラウザがふつうページに許すものは既定のままにせず塞いであります。

- **読み込める URL は 2 つだけです。** トップレベルのウィンドウが読み込めるのは `http://127.0.0.1:<port>/panel/` と `http://127.0.0.1:<port>/monitor/` だけで、`/` も `/api/` も `localhost` も別ポートも対象外です。それ以外への遷移とリダイレクトは取り消します。ただしモニタ内部の iframe は子フレームなので、意図的に対象外にしてあります。あのビューア URL は、モニタというページの一部そのものだからです。
- **新規ウィンドウと webview は作れません。** `window.open` は無条件で拒否します。
- **許可しているパーミッションは 1 つだけです。** サニタイズ済みのクリップボード**書き込み**を除き、すべて拒否します。その 1 つを許しているのは、アドレスバーを取り上げたことの代償です。パネルは OBS 用の URL を組み立てますが、選択のしようがないウィンドウからそれを取り出す手段はボタンしかありません。クリップボードの読み取りは、ここのどのページにも用のない操作なので拒否します。デバイス関連の許可もまとめて拒否します。
- **ウィンドウ名はメニューの名前で固定します。** どちらのページもブラウザのタブ用のタイトルを自分で設定しますが、ウィンドウ一覧に並ぶとその 2 つは見分けがつきません。そこで、ページが自分でタイトルを変えても無視します。

Chromium のスイッチは、アプリケーションが ready になる前に 4 つ設定します。3 つは、背面や隠れた状態のウィンドウが間引かれるのを止めるためのものです。パネルの後ろに回ったステージも描き続ける必要があるためです。残る 1 つは自動再生ポリシーで、クリックなしでステージが音を出せるのはこの設定によります。

## 設定

`HASHIDATE_CONTROL_PORT` は、制御サーバとウィンドウ 2 枚をまとめて別ポートへ移します。アドレスについて変えられるのはこれだけです。**ホスト**を指定する方法は、ここにも他のどこにも意図的に用意していません。[設定](getting-started.md#設定)を参照してください。

## パッケージ化していません

`yarn shell` は開発用チェックアウトの上で動くもので、シェルは自分のソースファイルの位置からリポジトリを解決します。`.app` もインストーラも自動更新もありません。これをパッケージ化すると、購入したアバターが配布物の中に入ってしまい、ライセンスが許していない状態になるためです。[アバター](avatars.md#ループバック限定なのはライセンスの都合)を参照してください。

ビルドを配布すると、一緒に持ち歩くべきものも変わります。同梱している IBM Plex は OFL-1.1 なので、そのライセンス文を同梱する必要が出てきます。
