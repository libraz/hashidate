# はじめに

hashidate は AITuber 用のアバターランタイムです。ブラウザで描いたキャラクターを、ローカルの HTTP API 越しに、1 発話ずつ外から動かします。キャラクターを持つのがレンダラ、台本を持つのが呼び出し側です。

これはアプリケーションではなくアダプタです。言語モデルについては何も知りませんし、どのモデルにも依存しません。依存関係に提供元の SDK は入っていませんし、設定する API キーもありません。人格もプロンプトも台本も会話の状態も持ちません。どれも呼び出し側のものです。届くのは発話 1 つ、つまり台詞と、それを何で届けるか（プリセット）と、どのショットで届けるか（ステージ）だけです。それを受け取って、キャラクターが喋り、演じます。

![境界を越えるもの](../images/boundary-ja.svg)

## なぜここに線を引くのか

線の左側は動きが速く、キャラクターを作る人のものです。どのモデルを使うか、どんな人格をどんなプロンプトで書くか、記憶をどう持つか、台本が何をどの順で言わせるか、言葉がコメント欄から来るのか音声認識から来るのかファイルから来るのか。線の右側は描画の問題で、左側が何に変わろうと変わりません。視線をどこへ動かすか、口をどれだけ開けたままにするか、髪が頭にどう遅れて付いてくるか。

この 2 つを分けておくと、モデルの差し替えがこちら側のコード変更にならず、レンダラの変更が呼び出し側の書き直しになりません。実際、hashidate は次のどれからでも使えます。

- 任意の言語で書いた LLM のループから、`POST /api/command` を呼ぶ
- MCP クライアントから、同じ API を 8 つのツールとして呼ぶ
- モデルを一切使わないシェルスクリプトから
- 配信パネルから、人が手で

4 つとも同じ経路を通るので、1 回の配信の中で混ぜて使えます。

## 境界を越えるもの

発話 1 つです。中身は小さなオブジェクトです。

| フィールド | 中身 |
|---|---|
| `text` | 喋る内容。角括弧で演出を書き込めます。 |
| `perform` | 表情とモーションをひと組にした名前、または個別指定。省略できます。 |
| `stage` | この行のカメラ・背景・音の部屋・スライド。省略できます。 |
| `reading` | 表記から読みが決まらないときの仮名。省略できます。 |

どこにもモデル名も声の種類もアバター名も出てきません。同じ発話が、別のキャラクターで、別の部屋で、別の声で、書き直さずにそのまま再生されます。

## 線の向こう側にあるもの

- **プロファイルの発見** — ボーン、指の命名族、ビセーム、瞬きシェイプ、描き起こし表情のグループを、モデルが実際に持っているものから解決します。ARKit 対応は前提ではなく判定結果です。
- **プリセット** — 表情とモーションをひと組の名前にしたもの。何の類かでグループ分けし、状態として出入りします。この 1 枚の表を、制御 API もパネルもアイドル時の自動モードも同じように話します。
- **モーション** — サッカードとばねで動く視線、呼吸と重心移動のアイドル、ジェスチャ表、跳躍、そして指先の位置から逆に解いた腕。関節の負担も返します。キーフレームのモーションは、組み込みの表に混ざらないまま、その隣にディスクから読み込みます。
- **表情** — ARKit かモデル自身のシェイプに合成する感情ブレンド、描き起こし表情、重ねる効果、瞼の伏せを持つ瞬きスケジューラ、テキスト起点のリップシンク。
- **揺れもの** — 髪と衣装のばねチェーン。コライダと尻尾つき。
- **衣装** — スロット、組み合わせのプリセット、それに伴う隠しシェイプ。モデルのメッシュから読み取ります。
- **背景と音の部屋** — 見える部屋が 4 つ、聞こえる部屋が 4 つ。別々の軸です。
- **スライド** — キャラクターの後ろに出す PDF。フレームと同じ解像度で描き、台本を書く側からはテキストとして読めます。
- **声の周りの音** — show ディレクトリから鳴らす BGM。声とは別の音量と別のエフェクトで、ページが持つ 1 つの音声グラフの下に置きます。
- **録画** — 本番に出ているレンダラ自身がファイルに書き出す一本。あいだにコンポジタは入りません。

## エンジンはアバターのデータを持たない

特定のモデル固有の事情——作者が何をどう名付けたか、衣装がどう組まれているか、目がどこまで動くか、どのシェイプが部品ではなく描き起こしの完成形なのか——はすべて記述子に置き、ランタイムはプロファイル越しにそれを読みます。アバターを差し替えるとは、このオブジェクトを差し替えることです。それ以外は変わりません。

このリポジトリが検証しているのはその一点です。作者の異なる 2 体、片方は ARKit の 52 ブレンドシェイプに対応し、もう片方は 1 本も持たない。これを同じエンジンと同じコマンド語彙で動かします。[アバター](avatars.md)を参照してください。

## やらないこと

hashidate はキャラクターを描いて動かすもので、AITuber そのものではありません。言語モデルも音声認識も配信の出力も持ちませんし、何を喋るかを決めるオーケストレータはこのリポジトリの外にいます。

一線を越えたのは音声合成だけで、それも `tools/tts/` の範囲に留めてあります。台詞を音声に変えるサイドカーで、HTTP 越しに呼ぶだけで import はしません。サイドカーが無くても全体はそのまま動き、口はテキストから組み立てた尺で動きます。[音声](speech.md)を参照してください。

ループバック限定であることも意図的です。`--host` フラグも CORS ヘッダもトンネルもありません。検証に使っているアバターは再配布が許されておらず、レンダラを外に出すのはコードの変更である前にライセンスの判断だからです。

エンジンはランタイムであってエディタではありません。リギング・ウェイト・衣装の作成は Blender の仕事で、`tools/blender` がその境目です。
