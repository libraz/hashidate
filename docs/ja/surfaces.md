# 操作面

ページは 3 つあります。違うのはできることではなく、立っている場所です。

## パネル（`/panel/`）

配信を回す場所です。レンダラも `AudioContext` も持たず、操作はすべて制御 API を通って出ていきます。つまり、ここで動く操作は言語モデルにも動かせる操作です。

タブは 8 枚です。Queue（台本、その履歴、途中への巻き戻し）、録画（台本の読み込み、一時停止、書き出し）、Perform、Voice、Slides、Dress、Tune、Inspect。アバター・画角・背景・アイドルの切替はプレビューの下にあります。この 4 つは絵を見て決めるものだからです。

プレビューがそのままカメラ操作です。ドラッグでキャラクターの周りを回り、ホイールで寄ります。埋め込まれたビューアが自分のカメラを読み返してパネルへ渡し、パネルはオーケストレータが送るのと同じ `camera` コマンドを送ります。本番のレンダラも一緒に回りますし、ショットの情報がどちらか一方のページだけに存在することもありません。

プレビューは常に無音です。同じコマンドを受け取る 2 つ目のレンダラなので、行はすべて要求しますし、音も最後まで再生します。口の動きが実際のキューと同じ時計で進むようにするためで、その音はゲイン 0 に流れ込みます。本番に出ている音とこちらの音を両方聞くと、1 行がコンマ何秒ずれて二重に聞こえます。どちらも聞こえないより悪い状態です。

この無音が、どのページが録画するかも決めています。録画に入るべきものは部屋が聞いたものなので、書き出すのはミュートされていないほうのレンダラです——[録画](recording.md)を参照。

タブの上には、OBS に必要なアドレスが 1 本だけ並びます。手で打つのではなく、サイズ・背景・資料・キャラクターの立ち位置・背景の透過を選ぶと `/?size=…` の形で組み上がります。貼り付けた瞬間からその設定は OBS のものなので、アプリ側の状態としては持ちません。

## レンダラ（`/`）

OBS が向くページです。開くとキャラクターだけが出ます。コンソールも HUD もカーソルもなく、カメラはポインタで動きません。本番前に切らなければならない既定値は、いつか本番に乗る既定値だからです。

`?console=1` で操作卓が戻ります。こちらは動いているシーンの**中**に手を入れます。`director.rig.measure('R')`、解剖学的な範囲に対する関節角、解決済みのプロファイル。2 つめの制御面ではなく開発用の計器で、「なぜこのポーズは変に見えるのか」に答えるためのものです。（`?stage=1` も受け付けますが、いまは既定と同じで何も足しません。既定が変わる前に設定されたブラウザソースに書かれているので残してあります。）

## ステージ（`/monitor/`）

同じレンダラを 16:9 にレターボックスして、それ以外は何も置かないページです。コンソールも操作系も、囲うアプリケーションもありません。オペレータが見る画面であり、このプロジェクトで唯一「聞くため」のページでもあります。OBS が開くブラウザソースの音は配信へ流れるので、ふつうの卓では部屋にいる人にキャラクターの声は届きません。

パネルのコードもキュー編集のコードも含みません。中身は `/` を指す iframe が 1 つと、その外側の黒帯だけです。帯を外に出してあるので、ウィンドウをどんな形に伸ばしてもレンダラはソースと同じアスペクト比を受け取ります。自分のアドレスに付いたものはそのまま素通しで、`?mute=1` も含みます。OBS 側でブラウザソースをモニタリングしていて部屋がすでに声を聞いている場合は、これで黙らせます。

## ネイティブシェル

`yarn shell` はページをビルドして、パネルとステージの 2 枚のウィンドウを開きます。制御サーバと、チェックアウトにあれば音声サイドカーもその下で起動し、終了時に一緒に落とします。同じチェックアウトのサーバがすでに動いていれば、置き換えずにそれを使います。立ち上げっぱなしの `yarn dev` を落とさないためです。**別の**チェックアウトのサーバだった場合は、黙って使わずに名指しで拒否します。他人のビルドから読み込まれた 2 枚のウィンドウは、レンダラが立ち上がらない状態と見分けがつかないからです。

これは 4 つ目の操作面ではなく、あくまで便利のためのものです。中で開いているのは同じループバックアドレスの同じ 3 ページで、配信に対してできることも同じ制御 API を通ります。足しているのはブラウザにできないことだけです。ウィンドウは前回置いた場所に戻り、ステージはページをクリックしなくても音を出しはじめ、`Window → Mute Stage` でこの機械が声を聞くかどうかを決められます。配信について、オーケストレータにも台本の 1 行にも答えられない唯一の問いです。番組の話ではなく、卓の話だからです。

## 計測の表示

`?debug=1` はレンダラが描くもう 1 つのもので、本番の画面に出しうる唯一のものです。呼吸・瞬き・視線・フレームレート、それにどのスライドが出ていてそのページが描き終わっているか。これをシェル風にフレームの隅へ出します。スライドの層より上に置いてあるので、スライドの区間でも隠れません。読むだけなので、本番中に出しても害がありません。バッククォートキーで切り替えます。実際の使い方は後者で、疑問が出たときに出して、数秒後に消します。

コマンドでもあります。知りたいのはたいてい目の前のページではなく、配信に出ている画面のことだからです。

```sh
yarn ctl debug          # 接続中のすべてのレンダラに出す
yarn ctl debug off
```

パネルではプレビューの上の measure ボタンです。プレビューにも出るのは、プレビューが同じコマンドを受け取っている 2 つ目のレンダラだからです。

**常設に見えて、意図的に保存しない唯一の設定です**。発話をまたいで残る設定——アバター、衣装、画角、背景、音の部屋——はすべて、レンダラが接続した瞬間に手渡される設定に畳み込まれます。これだけは意図的に外してあります。リハーサル中に出した計測値が、配信の頭で OBS がソースを読み直したときに独りでに戻ってくる。デバッグ用の表示が配信に乗る道筋はそれだけだからです。新しく接続したレンダラは、直前に何が送られていようと必ず消えた状態から始まります。

## 常設状態

パネルが操作面の全部で、レンダラは配信の頭に最後に開きます。そうできるのは、制御サーバが設定を保持しているからです。アバター、衣装、画角、背景、音の部屋、声の処理、調律は、選ばれた時点で常設状態に畳み込まれ、レンダラが接続した瞬間に、積んである台詞ごと手渡されます。配信中の再読み込みに耐えてきたのはこれのおかげです。

配信の内容が、ブラウザソースに設定した URL に入っていることはありません。

再現しないのは、設定ではなく一瞬だったものです。ジェスチャは勝手に終わり、表情はそれを上げた行とともに解除され、割り込みはもう起きてしまっています。1 時間後に接続したレンダラのためにそれを演じ直すのは、設定を復元することの反対です。
