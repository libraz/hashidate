# デスクトップのマスコット

```sh
yarn mascot
```

キャラクターをデスクトップに出します。ほかのものの上に重なる透明なウィンドウが 1 つ、全身で立ち、トレイアイコンから操作します。ランタイムのほかの部分と同じレンダラ、同じ制御サーバを別の開き方で開いたもので、机の前の人に反応したいプログラムは、このウィンドウが報告する接触を読めます。

[ネイティブシェル](shell.md)と同じく、開発用チェックアウトのための起動役で、パッケージ化していません。読み込むのはループバックのちょうど 1 つのアドレスだけです。

## 起動

| スクリプト | 内容 |
|---|---|
| `yarn mascot:build` | ビューアのページと、ウィンドウのプリロードスクリプト `dist/mascot/preload.cjs` をビルドします |
| `yarn mascot` | ビルドしてからマスコットを起動します |

シェルと同じく、制御サーバと、このチェックアウトにあれば音声サイドカーを起動します。このチェックアウトですでに応答しているサーバがあれば、それを使います。トレイから終了すると、自分が起動したものを止めます。Dock のアイコンは隠すので、トレイが唯一の窓口です。

## ウィンドウ

- **透明で枠なし**。常に最前面で、すべての Space に出ます。全画面のアプリの上には出ません。
- **キャラクターの外側はクリックが通ります。** ページがポインタとアバターの輪郭（6 px の余白つき）を照合し、ポインタが上にあるあいだだけウィンドウにマウスを取らせます。輪郭を出ると 200 ms 後にマウスを返します。それ以外の場所のクリックは、下にあるものに届きます。
- **全身。** ページはビューアのマスコットモードで、全身のフレームで開きます。
- **ほかのウィンドウの後ろに回っても描画を間引きません。**

### 表示モードと大きさ

| モード | ウィンドウの位置 |
|---|---|
| 高さいっぱい | 作業領域の全高で、右下の角に余白なしで置きます |
| 右下、左下 | 作業領域の角に、下端と横の端から 16 px あけて置きます |
| 自由 | ドラッグして置いた場所です |

どのモードでも、幅は高さの 0.45 倍です。隅と自由では、高さは作業領域の高さから 16 px を引いた値の `scale` 倍です。`scale` は 0.25 から 2.0 までで、両端で止まります。1.0 を超えるとウィンドウは作業領域より高くなり、上端は作業領域の上端に合わせ、足元は画面の下にはみ出します。縦のドラッグは元に戻り、横の移動だけが残ります。幅は作業領域の幅から 32 px を引いた値を超えず、超える大きさは頭打ちにして描画し、保存した `scale` はそのままです。メニューは 0.05 刻みで、ホイールは連続的に変えます。

- **ドラッグ。** キャラクターがフォーカスされていないとき、押したまま 4 px を超えて動かすと、ウィンドウが動きます。最初の移動でモードが「自由」に変わり、最後の移動から 300 ms 後に位置と scale を保存します。
- **大きさ。** キャラクターがフォーカスされているとき、ホイールで連続的に変わります。上に回すと大きく、下に回すと小さくなり、1 フレーム内の回転はまとめて反映します。トレイとコンテキストメニューは 0.05 刻みで変えます。隅のモードは隅を固定して大きさが変わり、自由は足元の位置を固定して変わります（作業領域より高くなった場合を除きます）。
- **「高さいっぱい」から**小さくしても大きくしても、その大きさで右下に移ります。大きくした場合は、全高のときより 16 px 左にずれます。
- **位置を戻す**と、右下で scale 0.5 になります。
- **ディスプレイ。** ウィンドウの上辺の中点があるディスプレイを使うので、下にはみ出した背の高いウィンドウも、頭のあるディスプレイに属します。保存した位置のディスプレイが見つからないときは、主ディスプレイの右下の隅に表示し、保存は上書きしません。ディスプレイが戻れば、マスコットも元の位置に戻ります。

### フォーカスと回転

キャラクターをクリックするとフォーカスされ、ポインタが掴む形になります。フォーカスが外れるのは、ポインタがマウスを返したとき、ページの外へ出たとき、ウィンドウがフォーカスを失ったとき、縮小でキャラクターがポインタの下から外れたときです。

| キャラクターが | ドラッグ | ホイール |
|---|---|---|
| フォーカスされている | カメラをキャラクターの周りに回す（1 フレームに 1 回） | ウィンドウの大きさを変える |
| フォーカスされていない | ウィンドウを動かす | 何もせず、横取りもしない |

向きはこのウィンドウだけのものです。`camera` コマンドではなく橋を通ります。コマンドは全レンダラが追うので、マスコットと一緒にパネルのプレビューや OBS まで回ってしまうからです。向きは `shell-state.json` に保存され、ページを読み込むたびに戻されます。コンテキストメニューの「正面を向く」で正面に戻ります。位置を戻しても向きは変わりません。

モード、scale、位置、向き、ミュートは、Electron のプロファイルの隣の `shell-state.json` に、シェル自身の状態と同じ場所へ保存します。

### メニュー

トレイアイコンには、表示と非表示、表示モード、大きさ、アバター、ミュート、終了があります。キャラクターを右クリックすると、表示モード、大きさ、衣装、正面を向く、位置を戻す、非表示が出ます。隠してもプロセスは動き続け、トレイから戻せます。モードと大きさが両方にあるのは、キャラクターがクリックできない場所にいるときも、トレイからなら操作できるからです。

## ウィンドウの橋

マウスを取るかどうかと、ウィンドウの移動や大きさの変更は、ページが決めてシェルが実行します。制御サーバを経由すると、輪郭を横切るポインタには遅すぎます。そのためプリロードスクリプトは、5 つの呼び出しだけを持つ `window.hashidateMascot` を公開します。

| 呼び出し | 効果 |
|---|---|
| `setInteractive(on)` | ウィンドウがマウスを取る、または通す |
| `moveBy(dx, dy)` | ウィンドウを画面のピクセル数だけ動かす |
| `scaleBy(factor)` | 大きさを `factor` 倍する（0.5 から 2） |
| `turnTo(angle)` | 回転が落ち着いた yaw と pitch を、シェルが保存するために渡す |
| `onShot(fn)` | 表示する向きを受け取る。読み込みのたびに保存された向き、正面を向いた後は正面。受け取りを止める関数を返す |

メインプロセスは、マスコット自身のページからの呼び出しだけを受け付け、引数をすべて検査します。大きさと向きはそこで正規化と範囲の制限を受け、有限の数でない引数は拒否されます。このオブジェクトは、OBS やステージを含むほかのどのページにもなく、橋のないページはこれまでどおりに動きます。コマンドも報告もファイルへのアクセスも、この橋は通りません。

## ページ

マスコットのページは `/?mascot=1&transparent=1` で、ビューアの `mascot` 表示モードに背景透過を組み合わせたものです。ブラウザで開いても橋がないので、ポインタには反応せず、接触も報告されません。このモードが変えるのは最初のカットを全身にすることだけで、絵のほかの部分は変わりません。[レンダラの URL](surfaces.md#レンダラの-url)を参照してください。

シェルのウィンドウが読み込めるのは `/panel/` と `/monitor/` で、マスコットのウィンドウが読み込めるのはこの 1 ページだけです。形は 2 つで、`/?mascot=1&transparent=1` と、末尾に `&mute=1` を足したものです。それ以外のパス、クエリ、フラグメント、ホスト、ポートへの遷移は取り消され、リダイレクトも同じです。ループバックのみという決まりは変わりません。ホストを設定する手段も、CORS ヘッダもありません。

## 接触

接触はセッションイベントとして制御サーバに報告されるだけです。キャラクターがそれにどう応えるかは、イベントの末尾を読む呼び出し側が決めます。`say` が起こしたものではない、レンダラが報告するイベントは、接触だけです。

| イベント | 発生するとき |
|---|---|
| `touch.tap` | その場で押して離したとき。350 ms 以内に続けたタップは数が増え、1 回ごとに 1 件を出し、上限は 10 です |
| `touch.hold` | 600 ms 押し続けたとき。1 回だけ、`count` は 1 で報告します。離してもタップは出ません。そのあと 4 px を超えて動かすとドラッグになります |

どちらにも、次の任意の項目が付きます。

| 項目 | 値 |
|---|---|
| `part` | `head`、`torso`、`arm`、`hand`、`leg`。ポインタの下にある面で、最も重みの大きいボーンから決めます。首と目は `head`、鎖骨は `arm` に入ります |
| `side` | 左右のある部位なら `L` か `R`。`head` と `torso` には付きません |
| `count` | 1 から 10。連続タップの中で何回目か |

ページは `src/viewer/control-client.ts` の `ControlClient.pushEvent(event)` で送ります。ターンの境界と同じく即座に送られ、報告タイマーの次の拍を待ちません。

### 読み手は知らないものを読み飛ばす

レンダラの報告は厳密なままなので、形の崩れたイベントは拒否されます。`GET /api/state` と `GET /api/events` の読み手は寛容です。`sessionEventsSchema` は、検証に通らない要素を落とし、残りの一覧を保ちます。たとえば読み手が書かれたあとに足されたイベントの種別や `part` の値です。両端のプロセスは別々のリリースサイクルで動くので、閉じた一覧を厳密に読むと、新しい種別が増えるたびに古い読み手すべてで例外が出ます。

そのため、種別や `part` の値を足しても、このスキーマを持つ読み手は壊れません。持っている読み手は次のとおりです。

- このチェックアウトの CLI（`watch`、`inspect`、`show`）、MCP アダプタ、パネル、シェルのヘルスプローブ。再起動後に有効になります。
- `src/control` の制御クライアントと、それを import するもの。

## 更新したあと

- **更新前に起動した読み手は再起動が要ります。** 長く動いている MCP サーバや、古い `ControlClient` を持ち続けるスクリプトなど、接触イベントが入る前に `/api/state` を読んでいたプロセスは、一覧が閉じているので、接触が届くと例外を出します。
- **更新前に起動した制御サーバも再起動が要ります。** マスコットはすでに応答しているサーバを使いますが、そのサーバは接触を含むページの報告を丸ごと拒否します。接触だけでなく、ターンのイベントも届かなくなります。サーバを再起動すれば直ります。
- 接触を出すのはマスコットだけです。起動していないあいだは、新しい種別がワイヤに流れることはありません。

## シェルとプロファイルを共有する

シェルとマスコットは、1 つのレンダラと 1 つの声を 2 通りに開いたものです。両方が動くと、すべての行を二重にしゃべってしまいます。そのためチェックアウトごとの Electron プロファイルを 1 つだけ共有し、Chromium のスイッチも、シングルインスタンスのロックも同じで、持てるのは片方だけです。

| 状況 | 起きること |
|---|---|
| マスコットが動いていて `yarn shell` を起動した | シェルはロックを取れず、2 回目の起動のときと同じく終了コード 0 で終わります。マスコットは何もしません |
| シェルが動いていて `yarn mascot` を起動した | マスコットはロックを取れず、何も開かずに終了コード 75 で終わります。シェルは、2 回目の起動のときと同じくウィンドウを前に出します |
| `yarn mascot` を 2 回起動した | 終了コード 75 で終わります |

75 は `EX_TEMPFAIL` です。マスコットを起動するプログラムは、「すでに 1 つ動いている」ことをクラッシュと区別でき、再起動を試みずに済みます。トレイから終了すると 0 で終わり、人が閉じたことを表します。起動に失敗したマスコットは 1 で終わります。

## ミュート

トレイのミュートは、ウィンドウを `/?mascot=1&transparent=1&mute=1` で開き直し、その選択を保存します。レンダラが音を出すかどうかは URL だけで決まるので、アドレスを変えずにページを黙らせる呼び出しはありません。

ミュートしたマスコットも、すべての行の合成を求め、音量ゼロのゲインへ再生します。API から見える範囲では、しゃべっているマスコットと同じに振る舞います。`GET /api/state` は、どのレンダラがミュートかを返しません。呼び出し側はミュートしたマスコットと、黙っているだけのマスコットを区別できず、知る必要があるプログラムは、自分で開いたものでなければなりません。
