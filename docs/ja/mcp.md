# MCP アダプタ

`yarn mcp` は、同じ制御 API を MCP サーバとして話します。stdio なのでクライアント側がプロセスを起動します。起動しっぱなしにするものも、説明すべき 2 つめの待受口も増えません。既定と違う制御サーバを指すときは `--base` を渡します。

```json
{
  "mcpServers": {
    "hashidate": { "command": "yarn", "args": ["mcp"], "cwd": "/path/to/hashidate" }
  }
}
```

## ツールは 8 つ

| ツール | 何をするか |
|---|---|
| `speak` | 台詞をキューに積みます。数行が 1 回の呼び出しで届き、各 `text` に演技、ショット、ページ、BGM のインラインキューを書けます。 |
| `status` | 分岐に使う値。発話中かどうか、積まれている数、出ている表情とモーション、関節の負担。 |
| `interrupt` | 台詞を切って、積んだ分も捨てます。 |
| `react` | それ以外のうち即時のもの。プリセット、ジェスチャ、視線。 |
| `stage` | それ以外のうち常設のもの。カメラ、背景、音の部屋、スライド。 |
| `revise` | 積んだ行を直します。 |
| `deck` | スライドを読みます。それについての台本を書くためのものです。 |
| `bgm` | ローカルの MP3/FLAC を一覧・再生し、音量、ループ、BGM 専用の libsonare エフェクトを設定します。 |

語彙は `hashidate://vocabulary` というリソースで、言い終えた行も同じくリソースとして読めます。

## 2 つめの制御面ではなく、言い換え

どのツールも[制御 API](control-api.md) のエンドポイントそのもので、この層は判断を持ちません。足しているのは次の 3 つで、これ以下なら作る意味がありません。

- **id がツールのスキーマに入っています**。`perform`・`expression`・`gesture`・`backdrop`・`room` は、いま立っているアバターが実際に持つ id に絞られます。アバターを替えれば組み直され、一覧が変わったことが通知されます。スキーマを読むモデルは、プロンプトを読むモデルのようには id を捏造しません。
- **断った呼び出しには返事があります**。制御 API は読めないコマンドを黙って捨てます。別リリースサイクルの 2 プロセスの間ではそれが正しく、呼び手がモデルのときは誤りです。喋ったことにして先へ進んでしまうからで、そこでこの層は先に検証し、何も送らずに、選ぶべきだった id の一覧を添えて返します。
- **数行が 1 回の呼び出しで届きます**。理由は[まとめて送る](control-api.md#まとめて送る)にあります。

## 台詞の行き先

台詞は `say` としてではなくサーバのキューに入ります。ビューアを読み込み直しても残り、パネルに並ぶので並べ替えも書き直しもでき、`source: mcp` が付くのでコメントや手打ちと見分けられます。

## `speak` のキュー記法

`text` フィールドには従来の `[performanceId]` 省略記法と、次の型付き形式を書けます。

```text
[@perform id] [@expression id] [@gesture id] [@hop id]
[@camera face|bust|upper|full] [@slide 3]
[@bgm play] [@bgm play track filename] [@bgm pause] [@bgm stop]
```

`[@bgm play]` は選択中のトラックを再開します。`play` の後ろは正確な BGM ファイル名の末尾全体として扱うため、空白と日本語を含められます。プリセット、表情、ジェスチャ、跳躍の動的 id にも同じ末尾全体の規則を使います。`[` と `]` は予約文字です。型付きキューは通常の台詞テキストとして `speak` と台本のテキストを通ります。`room`、`backdrop`、`deck`、`place` は行頭の `stage` 設定に残ります。BGM の音量、ループ、DSP はパネルまたは `bgm` ツールの `settings` で操作します。相対ページはインラインキューに含まれません。タイミングは[台詞とキュー](lines-and-cues.md)を参照してください。

## BGM

`bgm` を `action: "list"` で呼ぶと `show/bgm/` を再走査し、後続の `play` が受け取る正確なファイル名を返します。他の action は `play`・`pause`・`resume`・`stop`・`settings` です。音量とループは個別に変えられ、`dsp` では BGM だけの音色、コンプレッション、ステレオ幅、リバーブを操作できます。[BGM](bgm.md)を参照してください。

`status` には、サーバーが持つ BGM の再生状態と解決済み設定も入ります。再生中か、レンダラがエフェクトなしの再生へ退避したかを呼び出し側から判定できます。

## 意図的に無いもの

`voice` と `tune` は置いていません。声をどう混ぜるか、調律の層をどこに置くかは、実際の音と実際の描画を前にして耳と目で決めるものです。送った結果を聞くことも見ることもできない呼び手が決めるものではありません。

駆動しているモデルについての情報も持ちません。stdio の向こうにどのモデルがいるのかをアダプタは知りませんし、その答えが変わっても中身は何も変わりません。
