# アバター

エンジンはアバターのデータを一切持ちません。特定のモデル固有の事情はすべて `src/avatars` の記述子に置き、ランタイムはプロファイル越しにそれを読みます。アバターを追加するには、記述子ファイルを作成し、`src/avatars/index.ts` に登録します。

**クローンしただけの状態にアバターは入っていません**。ここの記述子が指す `public/models/<id>.glb` は git 管理外なので、チェックアウトして最初にやることはモデルを用意することです。[自分のモデルを載せる](#自分のモデルを載せる)を参照してください。

```sh
yarn ctl avatar manuka
yarn ctl vocab
```

`avatar` は、他のすべてのコマンドが話しかける相手（セッション）ごと差し替える唯一のコマンドです。そのためレンダラは、モデルが立つまで後続のコマンドを保持します。着替えまで 1 つの batch で送っても、書いたとおりに動きます。

## 語彙はモデルから発見する

そのモデルに何を頼めるかは、モデルが実際に持っているものから解決します。ボーン、指の命名族、ビセーム、瞬きシェイプ、描き起こし表情のグループ、衣装のメッシュです。ARKit 対応は前提ではなく判定結果です。

そのため `GET /api/vocabulary` は定数ではなく、モデルについての報告書になります。作者の異なる 2 体、片方は ARKit の 52 ブレンドシェイプに対応し、もう片方は 1 本も持ちません。これを同じエンジンと同じコマンド語彙で動かすことが、このリポジトリが検証している点です。

## 記述子で宣言できること

名前やシェイプのほかに、そのモデルの衣装が必要とするものを記述子に持たせられます。

- `armRest` — キャラクター空間での腕の休めの向きです。広いスカートのように、腕を体から離しておく必要がある衣装のためのものです。省いたスロットは標準の立ち姿のままで、ジェスチャーは宣言した向きから始まります。
- スプリンググループの `anchor` — グループの根を、すでにシミュレートされているボーンに重みを振った 1 点へ付けます。衣装の一部が、載っている肌に追従します。
- 保持した PBR マテリアルの `reflection` — ランタイム自前のスタジオ環境をどれだけ映すかを決めます。指定がないと、マテリアルが見るのはシーン環境だけです。背景がなければ空なので、金属は暗く描かれます。

## 立ち姿勢の脚

プロファイルは VRChat、Unity、VRM の骨名から、左右の `upperLeg`、`lowerLeg`、`foot`、`toe` を任意のスロットとして解決します。足の接地制御には、立った休止姿勢と、左右とも揃った股関節から足首までのチェーンが必要です。つま先は省略できます。各主要リンクは腰の下で親子として直接つながり、制御する骨のスケールは各軸で同じである必要があります。ルートやアーマチュアの非一様スケールには対応します。該当する脚がないリグ、座った休止姿勢、可動域を上書きしたアバターでは、脚の姿勢を変更しません。

対応する立ち姿勢のリグでは、呼吸や重心移動の間も、アバターのルートを基準にした足の休止位置と向きを保ちます。骨盤が下がると膝が曲がり、上方への移動で脚の長さが足りなくなる場合は骨盤を下げます。ジャンプ中は両足の接地点を空中の上昇量だけ持ち上げ、着地の沈み込みで再び固定します。脚の骨は回転だけで制御し、ローカルの位置やスケールを変えません。腕の到達位置と揺れものを計算する前に処理します。

## 衣装

スロット、組み合わせのプリセット、それに伴う隠しシェイプを、モデルのメッシュから読み取ります。

```sh
yarn ctl wear --slot outer none
yarn ctl wear --preset casual
```

## アセット

検証用の 2 体は市販の VRChat 向けモデルです。購入時のパッケージ、そこから取り出したメッシュとテクスチャ、ビューアが読む GLB は、いずれも git 管理外にしてあります。合わせて 1.5 GB あり、ここから再配布できるものでもありません。

3 体目の夜凪ねる（`neru`）の GLB は、このリポジトリのパイプラインではなく別の制作環境で書き出し、`public/models/neru.glb` に置きます。これも git 管理外で、再配布もできません。

パイプラインは購入パッケージを GLB に変換します。

```sh
make            # 各ターゲットの説明
make extract    # 購入したアーカイブを展開
make textures   # unitypackage  → PNG
make resize     # 4K            → Web 用に縮小
make glb        # FBX           → public/models/*.glb
```

`make check-assets` は、1 MB を超えるファイルが git に紛れ込んでいれば失敗します。パスの一覧ではなく、git が実際に追跡している中身を測ります。`.gitignore` は誰かが思いついたパスしか守れませんし、500 MB の塊が履歴に 1 度入れば取り返しがつかないためです。

## ループバック限定なのはライセンスの都合

検証に使っているアバターは、再配布の許されていない市販モデルです。ビューアと制御 API が `127.0.0.1` にしか bind せず CORS ヘッダも出さないのは、慎重を期しているからではなく**そのため**です。音声サイドカーはさらに踏み込んで、ポートを 1 つも開かず、自分のユーザーしか入れないディレクトリの UNIX ソケットで答えます。声が実在する人物の録音から複製したものだという、2 つめのより強い理由があるためです。そうできるのは、呼び手がレンダラの代わりに中継する制御サーバ 1 つだけだからです。

`--host` フラグも CORS ヘッダもトンネルもありません。レンダラを外に出す必要がいつか出てきたとしても、それはコードの変更である前にライセンスの判断になります。

`public/models/` の中身は、このリポジトリのライセンスの対象外です。チェックアウトして手に入るのはランタイムであって、それが動かしてきたキャラクターではありません。

## 自分のモデルを載せる

エンジンはランタイムであってエディタではありません。リギング・ウェイト・衣装の作成は Blender の仕事で、`tools/blender` がその境目です。そのパイプラインから出てきたモデルの記述子を `src/avatars` に作成します。`src/avatars/index.ts` で import し、`AVATARS` 配列へ追加すると、ランタイムから選択できます。

テストは GLB を読まず、コード上で合成のアバターを組み立てます。購入した 16 MB のモデルを必要とするテストは、それを買ったマシンでしか走らないためです。フィクスチャを足すのではなく `tests/helpers/scene.ts` を拡張してください。
