# アバター

エンジンはアバターのデータを一切持ちません。特定のモデル固有の事情はすべて `avatars/` 配下のファイルに置き、ランタイムはプロファイル越しにそれを読みます。制御サーバがファイルを検証して配信し、レンダラは受け取った内容からアバターを組み立てます。アバターを追加するにはファイルを 1 つ置くだけで、コードの変更も登録も要りません。

**クローンしただけの状態にアバターは入っていません**。`avatars/` と `public/models/` は空のまま出荷され、中身は git 管理外です。チェックアウトして最初にやることは、モデルを用意して記述することです。[自分のモデルを載せる](#自分のモデルを載せる)を参照してください。

形式のリファレンスは `src/protocol/avatars.ts` です。サーバとレンダラが同じこのスキーマで読み込みます。このページはフィールドの用途を説明し、正しい書き方の厳密な定義はそのファイルが担います。

## ファイルの置き場所

```
avatars/<id>.json             ランタイムが読むファイル（.yaml と .yml も使えます）
avatars/export/<id>.json      モデルを GLB に変換する手順。make が読み、ランタイムは読みません
public/models/<id>.glb        ビューアが読み込むモデル
```

id は拡張子を除いたファイル名です。64 文字以内で、先頭にドットを置けず、パス区切りや制御文字を含められません。Unicode の正規化だけが異なる 2 つのファイル名は、あいまいなものとして両方とも拒否されます。256 KiB を超えるファイルも拒否されます。

`--avatars <dir>` でディレクトリを移せます。`--motions` と同じ扱いです。中身は git 管理外です。ネイティブシェルには `Window → Open Avatars Folder` があります。

## 最小のファイル

`avatars/example.json` と、そのモデル `public/models/example.glb` です。

```json
{
  "label": { "en": "Example", "ja": "サンプル" },
  "separator": { "pattern": "^_{2,}(.+?)_{2,}$" },
  "presets": {
    "group": "Faces",
    "label": { "stripPrefix": "F_", "underscoresToSpaces": true }
  },
  "sway": {
    "groups": [{ "id": "hair", "label": { "en": "Hair", "ja": "髪" }, "stiffness": 0.4, "drag": 0.2, "childrenOf": ["Hair"] }]
  }
}
```

必須なのは `label` だけです。ほかを何も書かないアバターでも読み込まれ、エンジンが自力で解決できなかったものは、失敗にはならず語彙の中で報告されます。

```sh
yarn ctl avatars
yarn ctl avatar example
yarn ctl vocab
```

`avatar` は、他のすべてのコマンドが話しかける相手（セッション）ごと差し替える唯一のコマンドです。そのためレンダラは、モデルが立つまで後続のコマンドを保持します。着替えまで 1 つの batch で送っても、書いたとおりに動きます。

## フィールド

ファイル内のオブジェクトはすべて strict です。未知のキーは、そのパスを示すエラーになります。値の型が違う場合も同様です。ファイル名が id なので、`id` キーも未知のキーとして拒否されます。数値は有限でなければなりません。

| フィールド | 宣言する内容 |
|---|---|
| `label` | ピッカーに表示する名前で、`{ "en", "ja" }` の形です。必須です。 |
| `author` | モデルのクレジットで、`{ "en", "ja" }` の形です。 |
| `url` | ビューアが GLB を取りに行く場所です。省略すると `/models/<id>.glb` になります。[url](#url)を参照してください。 |
| `separator` | 作者がシェイプのグループ間に置くダミーシェイプに一致する[パターン](#パターン)です。グループ名を、ただ 1 つのキャプチャグループで取り出します。 |
| `gaze` | 実測した目・頭・首の可動限界（`eyeYaw`、`eyePitch`、`headYaw`、`headPitch`、`neckYaw`、`neckPitch`）です。省いたものはエンジンの保守的な既定値のままです。 |
| `shapes` | エンジン自前の候補リストでは解決できない、まばたき（`blink.both`、`blink.L`、`blink.R`）とビセームのスロットの名前です。 |
| `presets` | 描き起こし済みの顔全体の絵です。`group` はシェイプのグループ名、`exclude` は表情ではない調整用シェイプ、`emotion` は標準の感情と絵の対応、`composition` は絵がまばたきや発話と顔を分け合う方法、`hideGroup` は退避用シェイプのグループ名、`idleExclude` はアイドルの自動操作に選ばせない顔、`label` は[ラベル規則](#ラベル)です。 |
| `emotionShapes` | ARKit のシェイプを持たないモデル向けに、そのアバター自身のシェイプ名で書いた感情の合成です。 |
| `mouthShapePattern` | 発話中に口のレイヤーが受け持つシェイプのパターンです。 |
| `overlays` | 顔の上に重ねる描き起こしエフェクトのグループです。`group`、`exclude`、`label` は `presets` と同じです。 |
| `materials` | マテリアル名に対する `doubleSided`、`faceDecal`、`blendTransparent`、`preserveImported` の[パターン](#パターン)と、名前を指定した保持マテリアルの `metalness`、`roughness`、任意の `reflection` を設定する `preservedPbrOverrides` です。 |
| `wardrobe` | 各スロットの `slots`（`items` は `id`、`label`、`meshes`、`hide`）と、スロットにアイテムまたは `null` を割り当てる `presets`、スロットの上に出す `note` です。 |
| `sway` | 揺れもの（二次モーション）です。数値と根を持つ `groups` と、グループが名前で参照する `colliders` の集合を書きます。[揺れの調整](#揺れの調整)を参照してください。 |
| `drive` | `tail` で、どの揺れグループをシミュレートだけでなくポーズで動かすかを、`swing`、`lift`、`rest` とともに指定します。 |
| `script` | ビューアのスクリプトボタンで再生するデモの行です。各行は制御 API が受け取る turn の形です。 |
| `anatomy` | 意図的に人間ではないアバターのための関節テーブルです。 |
| `armRest` | キャラクター空間での腕の休めの向きです。広いスカートのように、腕を体から離しておく必要がある衣装のためのものです。省いたスロットは標準の立ち姿のままで、ジェスチャーは宣言した向きから始まります。 |

`gaze`、`presets`、`emotionShapes`、`mouthShapePattern`、`overlays` は `null` を受け付けます。省略と同じ意味で、書いておくとモデルを確認済みであることの記録になります。

揺れグループとマテリアルの中に、次の 2 つの指定があります。

- 揺れグループの `anchor` は、グループの根を、すでにシミュレートされているボーンに重みを振った 1 点へ付けます。衣装の一部が、載っている肌に追従します。
- 保持した PBR マテリアルの `reflection` は、ランタイム自前のスタジオ環境をどれだけ映すかを決めます。指定がないと、マテリアルが見るのはシーン環境だけです。背景がなければ空なので、金属は暗く描かれます。

### パターン

名前に一致させるフィールドは、文字列ではなくオブジェクトを取ります。

```json
{ "pattern": "^(Hair|Lash)", "ignoreCase": true }
```

`pattern` は JavaScript の正規表現のソースで、フラグは `ignoreCase` だけです。空のパターン、1024 文字を超えるパターン、コンパイルできないパターンは拒否されます。`separator` にはさらに、キャプチャグループがちょうど 1 つ必要です。そのグループが、区切りが開くシェイプグループの名前になります。

### ラベル

ラベル規則は、表示用にシェイプ名を整えます。

```json
{ "stripPrefix": "F_", "underscoresToSpaces": true }
```

`stripPrefix` は名前の先頭にあるときだけ、1 回取り除きます。続いて `underscoresToSpaces` が、すべての `_` を空白に置き換えます。どちらも省略でき、ほかのキーは受け付けません。結果は作者が絵につけた名前そのままなので、どちらの言語でも同じ表記になります。

### url

`url` はビューア自身のオリジンから取得されるため、`/models/name.glb` のようなルート相対パスでなければなりません。`//` で始めたり、`..`・`\`・`?`・`#` を含めたり、スキームを付けたりはできません。外部のモデルを指せないのは意図したもので、[ライセンスの都合](#ループバック限定なのはライセンスの都合)によります。

### YAML

同じフィールドを `.yaml` や `.yml` でも書けます。YAML を選ぶ理由はコメントを書けることです。値の理由を、その値のそばに残せます。例では JSON を使っています。

## エラー

読み込めないファイルは、そのファイルだけが除外されます。ほかのアバターは使えたままです。サーバはリクエストのたびにディレクトリを読み直すため、配信中に保存したファイルは、次にストリームを開いたときに現れます。すでに読み込み済みのアバターは、ファイルが変わっても再読み込みされません。

```sh
yarn ctl avatars
```

見つかったアバターをラベルと `url` とともに一覧し、拒否されたファイルをその横に、理由と問題のあるキーのパスとともに並べます。レンダラも、一覧を取得するときに同じ理由をブラウザのコンソールへ警告として出します。

ディレクトリにアバターが 1 つもなければ、ステージは空のままで、コンソールにはピッカーの代わりにその旨の表示が出ます。

## 語彙はモデルから発見する

そのモデルに何を頼めるかは、モデルが実際に持っているものから解決します。ボーン、指の命名族、ビセーム、瞬きシェイプ、描き起こし表情のグループ、衣装のメッシュです。ARKit 対応は前提ではなく判定結果です。

そのため `GET /api/vocabulary` は定数ではなく、モデルについての報告書になります。作者の異なる 2 体、片方は ARKit の 52 ブレンドシェイプに対応し、もう片方は 1 本も持ちません。これを同じエンジンと同じコマンド語彙で動かすことが、このリポジトリが検証している点です。

## 立ち姿勢の脚

プロファイルは VRChat、Unity、VRM の骨名から、左右の `upperLeg`、`lowerLeg`、`foot`、`toe` を任意のスロットとして解決します。足の接地制御には、立った休止姿勢と、左右とも揃った股関節から足首までのチェーンが必要です。つま先は省略できます。各主要リンクは腰の下で親子として直接つながり、制御する骨のスケールは各軸で同じである必要があります。ルートやアーマチュアの非一様スケールには対応します。該当する脚がないリグ、座った休止姿勢、可動域を上書きしたアバターでは、脚の姿勢を変更しません。

対応する立ち姿勢のリグでは、呼吸や重心移動の間も、アバターのルートを基準にした足の休止位置と向きを保ちます。骨盤が下がると膝が曲がり、上方への移動で脚の長さが足りなくなる場合は骨盤を下げます。ジャンプ中は両足の接地点を空中の上昇量だけ持ち上げ、着地の沈み込みで再び固定します。脚の骨は回転だけで制御し、ローカルの位置やスケールを変えません。腕の到達位置と揺れものを計算する前に処理します。

## 衣装

スロット、組み合わせのプリセット、それに伴う隠しシェイプを、モデルのメッシュから読み取ります。

```sh
yarn ctl wear --slot outer none
yarn ctl wear --preset casual
```

## 揺れの調整

髪、スカートの裾、リボン、尻尾は、それ自体にアニメーションを持たないボーンです。その設定は制作ツールの側にあり、書き出しでは残りません。ボーンだけが GLB に届くので、どう動くかを表す数値は `sway` に書き直す必要があります。

パッケージが作者自身の物理設定を公開しているなら、その数値を引き継いでください。モデルが動くのを見ながら誰かが決めた値なので、出発点としてはそちらが優れています。ただし別のソルバ向けに決められた値なので、ここでも描画で確かめます。数値が無い場合は目で調整します。グループを 1 つずつ、描画を見ながら、布や髪に見えて棒に見えなくなるまで詰めます。

どちらの場合も、結果は画面で判断します。エンジン自身の定数も同じやり方で決めたもので、テストを通すために値を変えることはしません。

## 自分のモデルを載せる

エンジンはランタイムであってエディタではありません。リギング・ウェイト・衣装の作成は Blender の仕事で、`tools/blender` がその境目です。そのパイプラインから出てきたモデルに、上で説明した `avatars/` のファイルを 1 つ作成します。

### モデルを GLB に変換する

変換は `avatars/export/<id>.json` のエクスポートプロファイルで記述し、2 つの make ターゲットがそれを読みます。

```sh
make glb AVATAR=example        # FBX または blend → public/models/example.glb
make textures AVATAR=example   # 元の PNG       → Web 用サイズの PNG
```

ターゲットなしの `make` で、使えるターゲットの一覧が出ます。`BLENDER=<path>` で、`make glb` が使う Blender を別のものにできます。どちらのターゲットも、`AVATAR` がないとき、またはプロファイルが存在しないときは、使い方を表示して止まります。

プロファイルは JSON オブジェクトです。中のパスは、`make` を実行するリポジトリのルートからの相対です。

| キー | 宣言する内容 |
|---|---|
| `source` | 書き出す FBX または `.blend` です。ベンダーが `.blend` を同梱しているなら、そちらを選んでください。マテリアルがテクスチャに接続された状態で届きます。 |
| `extras` | メインのスケルトンに結合する追加の FBX で、衣装などです。省略できます。 |
| `textures` | 書き出しがテクスチャを読むディレクトリです。 |
| `textures_src` | `make textures` がコピー元にする、元の PNG のディレクトリです。省略できます。 |
| `resize` | `{ "match": "<glob>", "px": <n> }` のリストです。ファイル名に最初に一致した項目が長辺を決め、どれにも一致しないファイルは 1024 になります。省略できます。 |
| `separator` | 作者のグループ区切りシェイプに一致し、グループ名を取り出す正規表現で、プレーンな文字列で書きます。 |
| `keep_groups` | 残すシェイプのグループです。 |
| `keep_groups_by_mesh` | 特定のメッシュでだけ残すグループです。メッシュ名をキーにしたリストのオブジェクトで、省略できます。 |
| `keep_names` | 区切りの下にない単独のシェイプのうち、残すものに一致するパターンです。省略すると、`Hide` を含む名前を残します。 |
| `texture_by_material` | マテリアル名と、そのマテリアルが使う `textures` 内のテクスチャファイルの対応です。省略できます。 |

`make textures` は `sips` で縮小するので、macOS で動きます。

### シェイプのグループを残す・捨てる理由

市販のアバターは多くのシェイプキーを持ち、その大半は作者自身のツール向けの調整用シェイプです。すべて書き出すと GLB が重くなり、語彙もステージ上で意味を持たない名前で埋まります。そこで書き出しでは、グループ単位で残します。

シェイプキーはラベル付きのグループになっていて、各グループの先頭にはダミーの区切りシェイプがあります。プロファイルの `separator` がそれを見つけ、`keep_groups` が残す価値のあるグループを指名します。標準のブレンドシェイプのセット、作者自身の表情の絵、衣装を着たときに体が突き抜けないよう上げる退避用シェイプのグループです。区切りも残すので、ランタイムは GLB だけからグループ構成を再発見できます。記述子の `separator` や `presets.group` に同じ名前を書けるのはそのためです。

名前ではなくグループで絞るのは、アバター固有の表情の語彙を通すためです。描き起こしの顔には、外から見分けられる命名規則がありません。区切りの下にない単独のシェイプを持つメッシュは、標準の名前と `keep_names` で判断します。

捨てるグループは、名前で頼まれることがないものです。他の体向けの調整用シェイプや、書き出さない衣装のバリエーションがそれにあたります。`presets`、`wardrobe.hide`、`shapes` のどれかが参照しているシェイプのグループは残してください。GLB にない名前は、欠落として報告されます。

### 購入パッケージを展開する

展開は自動化していません。パッケージごとに形が違うためです。手順の大筋は共通です。

1. アーカイブを git の外のディレクトリに unzip します。`backup/` と `public/models/` の中身は git 管理外です。
2. FBX と、あれば `.blend` を探し、そのパスをプロファイルの `source` と `extras` に書きます。
3. `.unitypackage` は gzip 圧縮された tar です。テクスチャは `python3 tools/blender/extract_textures.py <package> <outdir> [パスに含まれる文字列]` で取り出します。文字列は Unity プロジェクト内のパスの絞り込みで、既定は `/Texture_1K/` です。出力先を `textures_src` に指定します。
4. `make textures AVATAR=<id>` を実行し、続けて `make glb AVATAR=<id>` を実行します。

`make check-assets` は、1 MB を超えるファイルが git に紛れ込んでいれば失敗します。パスの一覧ではなく、git が実際に追跡している中身を測ります。`.gitignore` は誰かが思いついたパスしか守れませんし、500 MB の塊が履歴に 1 度入れば取り返しがつかないためです。

## ループバック限定なのはライセンスの都合

市販のモデルは、一般に再配布が許されていません。ビューアと制御 API が `127.0.0.1` にしか bind せず CORS ヘッダも出さないのは、慎重を期しているからではなく**そのため**です。音声サイドカーはさらに踏み込んで、ポートを 1 つも開かず、自分のユーザーしか入れないディレクトリの UNIX ソケットで答えます。声が実在する人物の録音から複製したものだという、2 つめのより強い理由があるためです。そうできるのは、呼び手がレンダラの代わりに中継する制御サーバ 1 つだけだからです。

`--host` フラグも CORS ヘッダもトンネルもありません。レンダラを外に出す必要がいつか出てきたとしても、それはコードの変更である前にライセンスの判断になります。

`avatars/` と `public/models/` の中身は、このリポジトリのライセンスの対象外です。チェックアウトして手に入るのはランタイムであって、それが動かすキャラクターではありません。

テストは GLB を読まず、コード上で合成のアバターを組み立てます。購入した 16 MB のモデルを必要とするテストは、それを買ったマシンでしか走らないためです。フィクスチャを足すのではなく `tests/helpers/scene.ts` を拡張してください。
