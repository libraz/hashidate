# アバター

エンジンはアバターのデータを一切持ちません。特定のモデル固有の事情はすべて `avatars/` 配下のファイルに置き、ランタイムはプロファイル越しにそれを読みます。制御サーバがファイルを検証して配信し、レンダラは受け取った内容からアバターを組み立てます。アバターを追加するにはファイルを 1 つ置くだけで、コードの変更も登録も要りません。

**クローンしただけの状態にアバターは入っていません**。`avatars/` と `public/models/` は空のまま出荷され、中身は git 管理外です。チェックアウトして最初にやることは、モデルを用意して記述することです。[自分のモデルを載せる](#自分のモデルを載せる)を参照してください。

形式のリファレンスは `src/protocol/avatars.ts` です。サーバとレンダラが同じこのスキーマで読み込みます。このページはフィールドの用途を説明し、正しい書き方の厳密な定義はそのファイルが担います。

## どのモデルから始めるか

いちばん早いのは、パックのあるモデルを買うことです。`packs/<id>/` のパックには、そのモデルを調整したときの記述ファイルとエクスポートプロファイルが入っています。購入したパッケージを 1 コマンドでアバターにでき、目で見て合わせ直す前からこのドキュメントのとおりに動きます。パックは 2 つあり、どちらもエンジンの調整値を決めるときに見ていたモデルです。

| パック | モデル | 作者 | 入手先 | 顔 |
|---|---|---|---|---|
| `manuka` | マヌカ ver1.02 | ジンゴ（STUDIO JINGO） | [BOOTH](https://jingo1016.booth.pm/items/5058077) | ARKit のセットはなく、作者独自のシェイプキーを `emotionShapes` で合成します。 |
| `yoka` | 旅枕ヨカ 1.0.0 | コトブキヤ | [BOOTH](https://avatarchan.booth.pm/items/8217336)、[公式サイト](https://avatar.kotobukiya.co.jp/daminzoku/) | ARKit 52 と描き起こしの表情を持ち、`presets` で選びます。 |

エンジンが区別する 2 種類の顔を、この 2 体で両方とも押さえられます。どちらのライセンスも、レンダリングした映像の公開は認めており、モデルのデータの再配布は改変の有無を問わず認めていません。配信の前にそれぞれの規約を読んでください。[ライセンス](#ループバック限定なのはライセンスの都合)も参照してください。

VRChat・Unity・VRM・Mixamo のボーン名を持つ人型であれば、ほかのモデルでも読み込めます。その場合、揺れと表情は目で見ながら調整することになります。[自分のモデルを載せる](#自分のモデルを載せる)を参照してください。結果をパックにする方法は `packs/README.md` にあります。

## パックを取り込む

```sh
make import                                                    # パックの一覧と、各モデルの入手先
make import PACK=manuka PACKAGE=~/Downloads/MANUKA_ver1.02.zip
make import PACK=yoka PACKAGE=~/Downloads/TabimakuraYoka_Avatar_1.0.0.zip
```

`make import` は、zip を git 管理外の `unpacked/<id>/` に展開し、パックが指定する `.unitypackage` から FBX とテクスチャを取り出します。続けてパックの記述ファイルとエクスポートプロファイルを `avatars/<id>.json` と `avatars/export/<id>.json` に置き、`make textures` と `make glb` を実行します。リポジトリのルートで実行してください。エクスポートプロファイルが名指しするファイルのないパッケージは拒否します。パックに載っていないハッシュのパッケージは、警告を出したうえで取り込みます。すでにあるものは何も上書きしません。取り込み直すときは、`unpacked/<id>/` と、パックと中身の違う `avatars/` の記述ファイルを別の場所へ移してください。

この手順は macOS と Blender 5.2 LTS でのみ確認しています。`make textures` は macOS の `sips` で画像を縮小し、`make glb` は `BLENDER=<path>` で指定しない限り `/Applications/Blender.app` の Blender を使います。

### 結果を確かめる

```sh
make dev                     # 1 つ目の端末で
yarn ctl avatar manuka       # 別の端末で
yarn ctl avatars             # id が一覧にあり、拒否されたファイルも未解決の名前もないこと
yarn ctl vocab               # モデルから見つかった感情・描き起こしの表情・衣装
yarn ctl play demo --replace
```

`http://127.0.0.1:5173/` を開くと表示されます。`avatars` が読み込み結果を報告するには、レンダラが開いている必要があります。レンダラはアバターの一覧を接続時に読むので、取り込んだあとはページを再読み込みしてください。`avatar` の直後は、報告がまだ前のアバターを指していたり `loading` だったりします。指定したアバターの名前が出るまで `avatars` を実行し直してください。`yarn ctl avatars` が `loaded: manuka (ready) nothing unresolved` と出し、アバターが立ち、まばたきし、デモの台詞に口を合わせていれば取り込みは完了です。未解決の報告には、記述ファイルが名指ししているのに GLB にないボーン・シェイプ・衣装のメッシュ・揺れのグループ・尻尾が名前つきで並びます。パックなら空になるはずです。名前が出た場合は、パッケージがパックの確認した版と違っています。その名前を記述ファイルの中で探し、[モデルを調べる](#モデルを調べる)の方法で正しい名前に直してください。

## ファイルの置き場所

```
avatars/<id>.json             ランタイムが読むファイル（.yaml と .yml も使えます）
avatars/export/<id>.json      モデルを GLB に変換する手順。make が読み、ランタイムは読みません
public/models/<id>.glb        ビューアが読み込むモデル
```

id は拡張子を除いたファイル名です。64 文字以内で、先頭にドットを置けず、パス区切りや制御文字を含められません。Unicode の正規化だけが異なる 2 つのファイル名は、あいまいなものとして両方とも拒否されます。256 KiB を超えるファイルも拒否されます。

`--avatars <dir>` でディレクトリを移せます。`--motions` と同じ扱いです。中身は git 管理外です。ネイティブシェルには `Window → Open Avatars Folder` があります。

## 最小のファイル

`avatars/example.json` と、そのモデル `public/models/example.glb` です。

```json
{
  "label": { "en": "Example", "ja": "サンプル" },
  "separator": { "pattern": "^_{2,}(.+?)_{2,}$" },
  "presets": {
    "group": "Faces",
    "label": { "stripPrefix": "F_", "underscoresToSpaces": true }
  },
  "sway": {
    "groups": [{ "id": "hair", "label": { "en": "Hair", "ja": "髪" }, "stiffness": 0.4, "drag": 0.2, "childrenOf": ["Hair"] }]
  }
}
```

必須なのは `label` だけです。ほかを何も書かないアバターでも読み込まれ、エンジンが自力で解決できなかったものは、失敗にはならず `yarn ctl avatars` で報告されます。

```sh
yarn ctl avatars
yarn ctl avatar example
yarn ctl vocab
```

`avatar` は、他のすべてのコマンドが話しかける相手（セッション）ごと差し替える唯一のコマンドです。そのためレンダラは、モデルが立つまで後続のコマンドを保持します。着替えまで 1 つの batch で送っても、書いたとおりに動きます。

## フィールド

ファイル内のオブジェクトはすべて strict です。未知のキーは、そのパスを示すエラーになります。値の型が違う場合も同様です。ファイル名が id なので、`id` キーも未知のキーとして拒否されます。数値は有限でなければなりません。

| フィールド | 宣言する内容 |
|---|---|
| `label` | ピッカーに表示する名前で、`{ "en", "ja" }` の形です。必須です。 |
| `author` | モデルのクレジットで、`{ "en", "ja" }` の形です。 |
| `url` | ビューアが GLB を取りに行く場所です。省略すると `/models/<id>.glb` になります。[url](#url)を参照してください。 |
| `separator` | 作者がシェイプのグループ間に置くダミーシェイプに一致する[パターン](#パターン)です。グループ名を、ただ 1 つのキャプチャグループで取り出します。 |
| `gaze` | 実測した目・頭・首の可動限界（`eyeYaw`、`eyePitch`、`headYaw`、`headPitch`、`neckYaw`、`neckPitch`）です。省いたものはエンジンの保守的な既定値のままです。 |
| `shapes` | エンジン自前の候補リストでは解決できない、まばたき（`blink.both`、`blink.L`、`blink.R`）とビセームのスロットの名前です。 |
| `bones` | スロットごとのボーン名のリストです（`hips`、`spine`、`chest`、`neck`、`head`、`eye.L`、`upperArm.R`、`toe.L` など）。汎用の候補リストでは届かない命名のリグ向けです。[ボーン名](#ボーン名)を参照してください。 |
| `fingers` | 指のチェーンをキー（`thumb.L`、`index.R` など）ごとに、基節を先頭にしたボーン名のリストで書きます。 |
| `presets` | 描き起こし済みの顔全体の絵です。`group` はシェイプのグループ名、`exclude` は表情ではない調整用シェイプ、`emotion` は標準の感情と絵の対応、`composition` は絵がまばたきや発話と顔を分け合う方法、`hideGroup` は退避用シェイプのグループ名、`idleExclude` はアイドルの自動操作に選ばせない顔、`label` は[ラベル規則](#ラベル)です。 |
| `emotionShapes` | ARKit のシェイプを持たないモデル向けに、そのアバター自身のシェイプ名で書いた感情の合成です。 |
| `mouthShapePattern` | 発話中に口のレイヤーが受け持つシェイプのパターンです。 |
| `overlays` | 顔の上に重ねる描き起こしエフェクトのグループです。`group`、`exclude`、`label` は `presets` と同じです。 |
| `materials` | マテリアル名に対する `doubleSided`、`faceDecal`、`blendTransparent`、`preserveImported` の[パターン](#パターン)と、名前を指定した保持マテリアルの `metalness`、`roughness`、任意の `reflection` を設定する `preservedPbrOverrides` です。`metalness` と `roughness` は 0 から 1 の範囲、`reflection` は負にできません。範囲外のファイルは、その値のパスを示して拒否されます。 `toon` は、作者が lilToon で設定した見た目をマテリアルに与えます。[トゥーンマテリアル](#トゥーンマテリアル)を参照してください。 |
| `wardrobe` | 各スロットの `slots`（`items` は `id`、`label`、`meshes`、`hide`）と、スロットにアイテムまたは `null` を割り当てる `presets`、スロットの上に出す `note` です。 |
| `sway` | 揺れもの（二次モーション）です。数値と根を持つ `groups` と、グループが名前で参照する `colliders` の集合を書きます。[揺れの調整](#揺れの調整)を参照してください。 |
| `drive` | `tail` で、どの揺れグループをシミュレートだけでなくポーズで動かすかを、`swing`、`lift`、`rest` とともに指定します。 |
| `script` | ビューアのスクリプトボタンで再生するデモの行です。各行は制御 API が受け取る turn の形です。 |
| `anatomy` | 意図的に人間ではないアバターのための関節テーブルです。 |
| `armRest` | キャラクター空間での腕の休めの向きです。広いスカートのように、腕を体から離しておく必要がある衣装のためのものです。省いたスロットは標準の立ち姿のままで、ジェスチャーは宣言した向きから始まります。 |
| `extras` | ツールが自分用に残すデータで、glTF の `extras` と同じく、ツールの名前をキーにして置きます。ランタイムは読みません。ファイルへ統合する制作ツールは、自分が書き込んだ項目をここに記録できます。 |

`gaze`、`presets`、`emotionShapes`、`mouthShapePattern`、`overlays` は `null` を受け付けます。省略と同じ意味で、書いておくとモデルを確認済みであることの記録になります。

揺れグループとマテリアルの中に、次の 2 つの指定があります。

- 揺れグループの `anchor` は、グループの根を、すでにシミュレートされているボーンに重みを振った 1 点へ付けます。衣装の一部が、載っている肌に追従します。
- 保持した PBR マテリアルの `reflection` は、ランタイム自前の金属用環境をどれだけ映すかを決めます。この環境は暗いスタジオにソフトボックスを3枚置いたもので、いちばん明るい1枚は標準のキーライト側にあります。そのため体の向きが変わると、映り込みが明暗の境目をまたいで動きます。どの部屋を出していても同じで、スライド表示中は部屋そのものがありません。指定がないと、マテリアルが見るのはシーン環境だけです。背景がなければ空なので、金属は暗く描かれます。

### ボーン名

プロファイルは各スロットについて、ファイルに書かれた名前、続いて自前の汎用候補（VRChat、Unity、VRM、Mixamo の各系統）の順に試し、最初に存在したボーンを採用します。名前を書くと、検出を止めずに上書きできます。指のチェーンは、基節と中節が解決できれば `fingers` の指定を使い、そうでなければ汎用の指パターンに進みます。

```json
{
  "bones": { "upperArm.L": ["Arm_Left"], "chest": ["Torso"] },
  "fingers": { "index.L": ["IdxA_L", "IdxB_L", "IdxC_L"] }
}
```

**名前は、ローダーによる名前の整形を済ませた形で照合します。** GLB ローダーはすべてのノード名を書き換えます。空白は `_` になり、`[ ] . : /` は取り除かれます。`Body.001` として書き出したボーンやメッシュはシーンでは `Body001` になり、`Lace Trim` は `Lace_Trim` になります。汎用候補を含め、ファイルの名前は比較の前に同じ書き換えを通すので、どちらの綴りでも使えます。先頭の `mixamorig` も取り除くため、`mixamorig:Hips`（読み込み後は `mixamorigHips`）は `Hips` に一致します。この書き換えは `bones`、`fingers` のボーン名と、衣装の `meshes` に適用されます。シェイプ名（`shapes`、`hide`、`emotionShapes`）はローダーが書き換えないので、書かれたとおりに比較します。

GLB が VRM のヒューマノイドマップを持つ場合は、それを `bones` の上書き（と `fingers` の上書き）として読み取ります。VRM 1.0 の `VRMC_vrm.humanoid.humanBones` も VRM 0.x の `VRM.humanoid.humanBones` も、各ヒューマノイドボーンのノードを示しており、どんな推測よりも確かな根拠になります。ファイル自身が書いた名前は、これまでどおり先に試します。

VRoid のシェイプ（ビセームの `Fcl_MTH_A` から `Fcl_MTH_O`、まばたきの `Fcl_EYE_Close` と `_L`/`_R` の組）も、汎用候補に含まれます。

### パターン

名前に一致させるフィールドは、文字列ではなくオブジェクトを取ります。

```json
{ "pattern": "^(Hair|Lash)", "ignoreCase": true }
```

`pattern` は JavaScript の正規表現のソースで、フラグは `ignoreCase` だけです。空のパターン、1024 文字を超えるパターン、コンパイルできないパターンは拒否されます。`separator` にはさらに、キャプチャグループがちょうど 1 つ必要です。そのグループが、区切りが開くシェイプグループの名前になります。

### ラベル

ラベル規則は、表示用にシェイプ名を整えます。

```json
{ "stripPrefix": "F_", "underscoresToSpaces": true }
```

`stripPrefix` は名前の先頭にあるときだけ、1 回取り除きます。続いて `underscoresToSpaces` が、すべての `_` を空白に置き換えます。どちらも省略でき、ほかのキーは受け付けません。結果は作者が絵につけた名前そのままなので、どちらの言語でも同じ表記になります。

### トゥーンマテリアル

`materials.toon` は、GLB のマテリアル名(表記そのまま)に、作者が lilToon で設定した見た目を対応づけます。エントリのあるマテリアルはその見た目で、ないマテリアルはこれまでどおり描かれます。`toon` が空でも何も変わりません。

```json
"toon": {
  "Skin": {
    "shadow": { "color": [0.99, 0.92, 0.9], "border": 0.39, "blur": 0.26, "strength": 1, "normalStrength": 1 },
    "outline": { "width": 0.07, "color": [0.3, 0.2, 0.2, 1], "fixWidth": 0.5 }
  }
}
```

必須なのは `shadow` だけです。ブロックの中では、`?` を付けた任意のキーを除いてすべて必須です。省略したブロックの機能は無効になります。

| ブロック | キー | 意味 |
|---|---|---|
| `shadow` | `color`、`border`、`blur`、`strength`、`normalStrength`、`receive`?、`mask`? | 影です。`color` は面が光から外れる側でアルベドにかける色、`border` と `blur` は境目の位置とぼかし、`strength` は影の強さ(0 で無効)、`normalStrength` は影がメッシュの法線ではなくノーマルマップにどこまで従うかです。`receive`(0 から 1、省略時は 0)は、落ち影で面をどこまで影側に入れるかです。影を落とすのは部屋の光で、部屋がないときは標準のキーライトがアバター自身に落とします。光を暗くするのではなく境目を動かすので、落ち影も影の色と境目で描かれます。`mask` は赤チャンネルで `strength` に掛かるテクスチャです。 |
| `shadow2` | `color`(RGBA)、`border`、`blur` | 影の内側に入る、さらに暗い 2 段目です。アルファが現れる割合になります。 |
| `asUnlit` | 数値、0 から 1 | 影を明るい側の色へ戻す割合です。省略すると 0 です。 |
| `normalMap` | `file`、`scale` | ノーマルマップとその強さです。`scale` が負なら反転します。 |
| `rimShade` | `color`(RGBA)、`border`、`blur`、`fresnelPower`、`normalStrength`、`mask`? | 縁の陰です。シルエットに沿って、影まで済んだ色に `color` を掛けていきます。アルファが現れる割合になります。`fresnelPower` は縁の項の指数で大きいほど細くなり、`normalStrength` は縁がノーマルマップにどこまで従うかです。`mask` は赤チャンネルで現れる割合に掛かるテクスチャです。 |
| `matcap` | `file`、`color`(RGBA)、`blend`、`mode`、`shadowMask`、`enableLighting`、`mainStrength`、`normalStrength`、`backfaceMask`、`lod`、`mask`? | 面に映すマテリアルキャプチャ画像です。`mode` は `normal`、`add`、`screen`、`multiply` のいずれかです。`shadowMask` は影の中で弱める度合い、`enableLighting` は光の色を、`mainStrength` はアルベドを掛ける度合い、`normalStrength` は参照がノーマルマップにどこまで従うかで、`backfaceMask` が 1 なら裏面では消えます。`lod` は画像を読む mip レベルで、大きいほどぼけます。`mask` は RGB でチャンネルごとに混ぜる強さに掛かるテクスチャです。 |
| `rim` | `color`(RGBA)、`border`、`blur`、`fresnelPower`、`normalStrength`、`backfaceMask`、`shadowMask`、`mainStrength`、`enableLighting`、`mode`、`dirStrength`、`dirRange`、`indirRange`、`indirColor`(RGBA)、`indirBorder`、`indirBlur`、`colorTex`? | 縁の光で、マットキャップの後に描きます。`fresnelPower` は縁の項の指数で、大きいほど細くなります。`dirStrength` は `color` の帯を光の当たる側に寄せ、同じ割合で反対側に `indirColor` の帯を足します。その帯の位置とぼかしが `indirBorder` と `indirBlur` です。`dirRange` と `indirRange` は、それぞれの帯を 1 に向けて広げ、-1 に向けて狭めます。ほかのキーの意味は `matcap` と同じです。`colorTex` は RGBA で両方の帯の色に掛かるカラーテクスチャです。 |
| `emission` | `color`、`map`? | マテリアル自身が出す光で、明るい側の色に加算されます。各チャンネルは 1 を超えられます。 |
| `outline` | `width`、`color`(RGBA)、`fixWidth`、`mask`? | シルエットの背後に描く輪郭線です。`width` は lilToon の単位(1 が 1 cm)、0 から 1 の `fixWidth` はカメラが 1 m より近づいたときに線を細くする度合い、`mask` は赤チャンネルで太さに掛かるテクスチャです。 |

色は lilToon で設定したままの sRGB で、各チャンネルは 0 から 1 です。ただし `emission.color` と、`matcap.color` の色のチャンネルは 1 を超えられます。`dirRange` と `indirRange` は -1 から 1 の範囲、`width`、`fresnelPower`、`lod` は負にできず、`scale` は任意の数値で、それ以外の数値はすべて 0 から 1 の範囲です。有限でない数値はすべて拒否され、どの階層でも未知のキーは拒否されます。

`file` は `shade.png` のような名前だけで、空にしたり `/`、`\`、`..`、`?`、`#` を含めたりできません。レンダラーは、モデルの GLB と同じ `/models/<id>/` から取得します。ファイルは `public/models/` の他の中身と同じく git に入れません。

`toon` の名前は `preserveImported` にも一致してはいけません。前者はマテリアルの見た目を置き換え、後者は取り込んだ見た目を残すので、そのファイルは名前を示して拒否されます。

### url

`url` はビューア自身のオリジンから取得されるため、`/models/name.glb` のようなルート相対パスでなければなりません。`//` で始めたり、`..`・`\`・`?`・`#` を含めたり、スキームを付けたりはできません。外部のモデルを指せないのは意図したもので、[ライセンスの都合](#ループバック限定なのはライセンスの都合)によります。

### YAML

同じフィールドを `.yaml` や `.yml` でも書けます。YAML を選ぶ理由はコメントを書けることです。値の理由を、その値のそばに残せます。例では JSON を使っています。

## エラー

読み込めないファイルは、そのファイルだけが除外されます。ほかのアバターは使えたままです。サーバはリクエストのたびにディレクトリを読み直すため、配信中に保存したファイルは、次にストリームを開いたときに現れます。すでに読み込み済みのアバターは、ファイルが変わっても再読み込みされません。

```sh
yarn ctl avatars
```

見つかったアバターをラベルと `url` とともに一覧し、拒否されたファイルをその横に、理由と問題のあるキーのパスとともに並べます。レンダラも、一覧を取得するときに同じ理由をブラウザのコンソールへ警告として出します。

一覧の下には、レンダラが読み込んだアバターが `loaded: <id> (<phase>)` の形で出ます。読み込みが済んでいれば、続けて `nothing unresolved` か、`unresolved:` とその内訳が出ます。内訳は、探したものを見つけられなかった層ごとの 1 行で、プロファイル（ボーン・viseme・まばたきのシェイプ）、衣装、揺れのチェーン、尻尾の駆動の順に、見つからなかった名前を並べます。読み込みに失敗した場合はそのエラーが出ます。同じ報告は `GET /api/state` の `avatar.problems` にも載ります。

ディレクトリにアバターが 1 つもなければ、ステージは空のままで、コンソールにはピッカーの代わりにその旨の表示が出ます。

## 語彙はモデルから発見する

そのモデルに何を頼めるかは、モデルが実際に持っているものから解決します。ボーン、指の命名族、ビセーム、瞬きシェイプ、描き起こし表情のグループ、衣装のメッシュです。ARKit 対応は前提ではなく判定結果です。

そのため `GET /api/vocabulary` は定数ではなく、モデルについての報告書になります。作者の異なる 2 体、片方は ARKit の 52 ブレンドシェイプに対応し、もう片方は 1 本も持ちません。これを同じエンジンと同じコマンド語彙で動かすことが、このリポジトリが検証している点です。

## 立ち姿勢の脚

プロファイルは VRChat、Unity、VRM の骨名から、左右の `upperLeg`、`lowerLeg`、`foot`、`toe` を任意のスロットとして解決します。足の接地制御には、立った休止姿勢と、左右とも揃った股関節から足首までのチェーンが必要です。つま先は省略できます。各主要リンクは腰の下で親子として直接つながり、制御する骨のスケールは各軸で同じである必要があります。ルートやアーマチュアの非一様スケールには対応します。該当する脚がないリグ、座った休止姿勢、可動域を上書きしたアバターでは、脚の姿勢を変更しません。

対応する立ち姿勢のリグでは、呼吸や重心移動の間も、アバターのルートを基準にした足の休止位置と向きを保ちます。骨盤が下がると膝が曲がり、上方への移動で脚の長さが足りなくなる場合は骨盤を下げます。ジャンプ中は両足の接地点を空中の上昇量だけ持ち上げ、着地の沈み込みで再び固定します。脚の骨は回転だけで制御し、ローカルの位置やスケールを変えません。腕の到達位置と揺れものを計算する前に処理します。

## 衣装

スロット、組み合わせのプリセット、それに伴う隠しシェイプを、モデルのメッシュから読み取ります。

アイテムの `meshes` に書いた名前は、同じ名前のメッシュに一致します。複数マテリアルのメッシュを分けた `<mesh>__<material>` と、ボーンと名前が重なったときに glTF が付ける `<mesh>_<n>` にも一致します。glTF のノード名にも一致し、そのノードのメッシュ、プリミティブが複数あるノードならそのすべてが対象になります。ノード名で書いた表は、エクスポーターがメッシュにどんな名前を付けたかに左右されません。

```sh
yarn ctl wear --slot outer none
yarn ctl wear --preset casual
```

## 揺れの調整

髪、スカートの裾、リボン、尻尾は、それ自体にアニメーションを持たないボーンです。その設定は制作ツールの側にあり、書き出しでは残りません。ボーンだけが GLB に届くので、どう動くかを表す数値は `sway` に書き直す必要があります。

パッケージが作者自身の物理設定を公開しているなら、その数値を引き継いでください。モデルが動くのを見ながら誰かが決めた値なので、出発点としてはそちらが優れています。ただし別のソルバ向けに決められた値なので、ここでも描画で確かめます。数値が無い場合は目で調整します。グループを 1 つずつ、描画を見ながら、布や髪に見えて棒に見えなくなるまで詰めます。

### グループを肌に付ける

`anchor: { "source": "bone-metadata" }` は、アンカーをファイルではなくグループの根のボーンから取ります。グループには `roots` に明示した根がちょうど 1 つ必要で、`childrenOf` は使えません。アンカーは制作ツール上でそのボーンに付ける `skinPointAnchor` というカスタムプロパティで、glTF の extras として書き出します（Blender のエクスポータでカスタムプロパティの書き出しが有効である必要があります）。値は次の形のオブジェクトです。

```json
{
  "influences": [
    { "bone": "Spine_Upper", "weight": 0.7, "position": [0.0, 0.12, -0.03] },
    { "bone": "Hips", "weight": 0.3, "position": [0.0, 0.31, -0.02] }
  ]
}
```

influence は 1 から 4 個です。`bone` は一意に解決でき、根自身でも根の子孫でもないボーンの名前、`weight` は負でなく合計が 1、`position` は肌の 1 点をそのボーンの逆バインド行列で変換したものです。根にこのプロパティがないグループや、検査に通らないグループは対象から外れ、プロファイルの missing に報告されます。同じオブジェクトを `anchor` に直接書くこともできます。

どちらの場合も、結果は画面で判断します。エンジン自身の定数も同じやり方で決めたもので、テストを通すために値を変えることはしません。

## 自分のモデルを載せる

エンジンはランタイムであってエディタではありません。リギング・ウェイト・衣装の作成は Blender の仕事で、`tools/blender` がその境目です。そのパイプラインから出てきたモデルに、上で説明した `avatars/` のファイルを 1 つ作成します。

近いほうのパックから始めると、作業の大半を省けます。ARKit のセットと描き起こしの表情を持つモデルなら `packs/yoka/`、独自のシェイプキーしかないモデルなら `packs/manuka/` です。手順は以下の節の順番どおりです。

1. モデルを調べ、区切りのシェイプ、シェイプのグループ、メッシュ、マテリアルを把握する。
2. エクスポートプロファイルを書き、`make textures` と `make glb` を実行する。
3. `label` だけの記述ファイルを書いて読み込み、`yarn ctl avatars` が未解決として報告する内容を読む。
4. その報告が空になるまでフィールドを足し、それからレンダリングを見ながら感情・揺れ・視線を調整する。

最後の手順はコマンドラインでは確かめられません。画面で自然に見えるかどうかが唯一の判定基準で、パックに既定値ではなく具体的な数値が入っているのはそのためです。自然に見えるようになったら、`packs/README.md` の手順でパックとして公開できます。

### モデルを調べる

何かを書く前に、パッケージの中身を Blender のヘッドレス実行で調べるスクリプトが 2 つあります。

```sh
blender -b -P tools/blender/inspect_fbx.py -- <model.fbx>
blender -b -P tools/blender/inspect_shapekeys.py -- <model.fbx|model.blend> [out.txt]
```

`inspect_fbx.py` は、アーマチュアとそのボーン数、メッシュごとの頂点数・三角形数・マテリアル数・シェイプキー数、マテリアルと画像の一覧を出します。メッシュ名とマテリアル名は、`wardrobe`・`materials`・`texture_by_material` が参照する名前です。`inspect_shapekeys.py` は、メッシュごとにシェイプキーを数え、ARKit 52・VRChat の viseme・よく使われる MMD の表情とどれだけ一致するかを採点します。どちらの例から始めるかは、この結果で決まります。`out.txt` を渡すと、すべてのシェイプキー名を順番どおりに書き出すので、区切りのシェイプとその下のグループを読み取って `separator` と `keep_groups` に使えます。

### モデルを GLB に変換する

変換は `avatars/export/<id>.json` のエクスポートプロファイルで記述し、2 つの make ターゲットがそれを読みます。

```sh
make glb AVATAR=example        # FBX または blend → public/models/example.glb と、トゥーン用テクスチャ
make textures AVATAR=example   # 元の PNG（サブディレクトリ込み） → Web 用サイズの PNG
```

ターゲットなしの `make` で、使えるターゲットの一覧が出ます。`BLENDER=<path>` で、`make glb` が使う Blender を別のものにできます。どちらのターゲットも、`AVATAR` がないとき、またはプロファイルが存在しないときは、使い方を表示して止まります。

プロファイルは JSON オブジェクトです。中のパスは、`make` を実行するリポジトリのルートからの相対です。

| キー | 宣言する内容 |
|---|---|
| `source` | 書き出す FBX または `.blend` です。ベンダーが `.blend` を同梱しているなら、そちらを選んでください。マテリアルがテクスチャに接続された状態で届きます。 |
| `extras` | メインのスケルトンに結合する追加の FBX で、衣装などです。省略できます。 |
| `textures` | 書き出しがテクスチャを読むディレクトリです。 |
| `textures_src` | `make textures` がコピー元にする、元のテクスチャのディレクトリです。サブディレクトリも対象です。省略できます。 |
| `resize` | `{ "match": "<glob>", "px": <n> }` のリストです。ファイル名に最初に一致した項目が長辺を決め、どれにも一致しないファイルは 1024 になります。省略できます。 |
| `separator` | 作者のグループ区切りシェイプに一致し、グループ名を取り出す正規表現で、プレーンな文字列で書きます。 |
| `keep_groups` | 残すシェイプのグループです。 |
| `keep_groups_by_mesh` | 特定のメッシュでだけ残すグループです。メッシュ名をキーにしたリストのオブジェクトで、省略できます。 |
| `keep_names` | 区切りの下にない単独のシェイプのうち、残すものに一致するパターンです。省略すると、`Hide` を含む名前を残します。 |
| `texture_by_material` | マテリアル名と、そのマテリアルが使う `textures` 内のテクスチャファイルの対応です。省略できます。 |

`make textures` は `sips` で縮小するので、macOS で動きます。`textures_src` を再帰的にたどり、見つけたファイルをすべて `textures` に `<stem>.png` として平らに書きます。そのため、配下のどこであってもステム（拡張子を除いた名前）が同じファイルが 2 つあると止まり、エラーに該当ファイルが列挙されます。その場合は `textures_src` をより狭いディレクトリに向けてください。

`make glb` は書き出しの後に、`avatars/<id>.json` の `materials.toon` が名指すテクスチャ（マスク、法線マップ、マットキャップなど）を `textures` から `public/models/<id>/` にコピーします。レンダラが取りに行くのはこの場所です。記述子がない、またはファイルを名指すものがないときは、`toon textures: nothing to copy` と表示してそのまま進みます。名指されたファイルが `textures` にないときは、足りないものをすべて列挙して失敗します。原因はたいてい、テクスチャが `textures_src` の外にあるか、`make textures` をまだ実行していないかのどちらかです。

### シェイプのグループを残す・捨てる理由

市販のアバターは多くのシェイプキーを持ち、その大半は作者自身のツール向けの調整用シェイプです。すべて書き出すと GLB が重くなり、語彙もステージ上で意味を持たない名前で埋まります。そこで書き出しでは、グループ単位で残します。

シェイプキーはラベル付きのグループになっていて、各グループの先頭にはダミーの区切りシェイプがあります。プロファイルの `separator` がそれを見つけ、`keep_groups` が残す価値のあるグループを指名します。標準のブレンドシェイプのセット、作者自身の表情の絵、衣装を着たときに体が突き抜けないよう上げる退避用シェイプのグループです。区切りも残すので、ランタイムは GLB だけからグループ構成を再発見できます。記述子の `separator` や `presets.group` に同じ名前を書けるのはそのためです。

名前ではなくグループで絞るのは、アバター固有の表情の語彙を通すためです。描き起こしの顔には、外から見分けられる命名規則がありません。区切りの下にない単独のシェイプを持つメッシュは、標準の名前と `keep_names` で判断します。

捨てるグループは、名前で頼まれることがないものです。他の体向けの調整用シェイプや、書き出さない衣装のバリエーションがそれにあたります。`presets`、`wardrobe.hide`、`shapes` のどれかが参照しているシェイプのグループは残してください。GLB にない名前は、欠落として報告されます。

### 購入パッケージを展開する

展開は自動化していません。パッケージごとに形が違うためです。手順の大筋は共通です。

1. アーカイブを git の外のディレクトリに unzip します。`backup/` と `public/models/` の中身は git 管理外です。
2. FBX と、あれば `.blend` を探し、そのパスをプロファイルの `source` と `extras` に書きます。
3. `.unitypackage` は gzip 圧縮された tar です。テクスチャと FBX は `python3 tools/blender/extract_textures.py <package> <outdir> [パスに含まれる文字列]` で取り出します。文字列は Unity プロジェクト内のパスの絞り込みで、既定は `/Texture_1K/` です。出力先を `textures_src` と `source` に指定します。マスクや法線マップはパッケージのサブディレクトリにあることが多いので、文字列がそれらを含むか確かめてください。
4. `make textures AVATAR=<id>` を実行し、続けて `make glb AVATAR=<id>` を実行します。
5. 作者が設定した見た目を取り込むには、次の節のとおり `lil_materials.py` を実行し、出力を記述子に入れます。その後で `make glb` をもう一度実行すると、名指されたテクスチャがコピーされます。

`make check-assets` は、1 MB を超えるファイルが git に紛れ込んでいれば失敗します。パスの一覧ではなく、git が実際に追跡している中身を測ります。`.gitignore` は誰かが思いついたパスしか守れませんし、500 MB の塊が履歴に 1 度入れば取り返しがつかないためです。

### Unity パッケージから見た目を読み取る

lilToon のマテリアルを同梱した `.unitypackage` には、作者の陰影が数値として入っています。`lil_materials.py` はそれを上記の `materials.toon` に変換するので、目で調整し直す必要はありません。

```sh
python3 tools/blender/lil_materials.py <package.unitypackage> \
  --folder /Materials/ --glb public/models/<id>.glb \
  --map mt_Outer_doubleS=Outer_double > toon.json
```

Python の標準ライブラリだけで動き、標準出力に `{"toon": {...}}` を書きます。これを記述子の `materials` に貼り付けます。それ以外の報告はすべて標準エラーに出ます。

| オプション | 意味 |
|---|---|
| `--folder` | Unity パスに含まれる文字列です。パスにこれを含む `.mat` だけを読むので、別のシェーダーのマテリアルを除くのに使います。この下に同名の `.mat` が 2 つあるとエラーになります。 |
| `--glb` | 書き出したモデルです。GLB から読んだマテリアル名が、出力のキーになります。 |
| `--map` | `<GLB のマテリアル名>=<.mat の名前>` で、繰り返し指定できます。名前が違うマテリアル用です。指定がなければ、GLB のマテリアルは同名の `.mat`、または `mt_` 接頭辞を外した名前の `.mat` に対応します。 |

マテリアルのシェーダーは guid で判別します。輪郭線パスを持つ種類には `outline` ブロックが付きます。lilToon の種類にない guid が出ると、マテリアル名を示して止まります。別シェーダーのフォルダーを `--folder` で除く必要があるのはこのためです。テクスチャは、パッケージ内のパスのステムに `.png` を付けた名前で指します。`make textures` が付ける名前と同じです。

標準エラーで `unmatched:` から始まる行は、`.mat` のない GLB のマテリアル、または GLB に対応するマテリアルのない `.mat` です。前者はこれまでどおりに描かれ、後者は取り込まれません。`warning:` から始まる行は、マテリアル名と、そのマテリアルが使っていてもレンダラが再現しない設定を示します。影の縁の色、3 段目の影、ベーステクスチャと異なる輪郭線テクスチャ、バックライト、2 つ目のマットキャップ、2・3 枚目のメインテクスチャ、グリッター、異方性、影色テクスチャ、透過マテリアルのアルファで薄まるリム、専用のノーマルマップを持つマットキャップが該当します。見た目は取り込まれますが、作者のレンダーとは差が出るという警告です。

## 見た目を確かめる

`yarn look` は、すべてのアバターを同じショットとステージで描画します。見た目の 2 つの版を、同じ画面で比べられます。

```sh
yarn look --label before
# 何かを変えてから
yarn look --label after --compare before
```

`backup/look/<label>/` に、アバター・ショット・ステージごとの PNG（`<avatar>-<shot>-<stage>.png`）と、それを表に並べた `index.html` を書きます。各フレームは購入したモデルの描画なので、git 管理外の `backup/` の下に置きます。すでにあるラベルは拒否されます。`--avatars yoka,manuka` でアバターを選べます。`--compare <label>` を付けると、表の各フレームの横にその前回の結果が並びます。ファイルへのリンクで、コピーはしません。

稼働中の `make dev` には繋ぎません。空いているポートに、`127.0.0.1` だけに束縛した制御サーバとビューアのサーバを自分で起動し、終わると止めます。そのため `make dev` が動いていても実行できます。フレームは目で見るためのものです。ポーズがアイドルで揺れるので、画素単位では一致しません。シェーダーのコンパイルに失敗したとき、または透明ステージのフレームが透明であるべき場所で透明でないときは、0 以外で終了します。

## ループバック限定なのはライセンスの都合

市販のモデルは、一般に再配布が許されていません。ビューアと制御 API が `127.0.0.1` にしか bind せず CORS ヘッダも出さないのは、慎重を期しているからではなく**そのため**です。音声サイドカーはさらに踏み込んで、ポートを 1 つも開かず、自分のユーザーしか入れないディレクトリの UNIX ソケットで答えます。声が実在する人物の録音から複製したものだという、2 つめのより強い理由があるためです。そうできるのは、呼び手がレンダラの代わりに中継する制御サーバ 1 つだけだからです。

`--host` フラグも CORS ヘッダもトンネルもありません。レンダラを外に出す必要がいつか出てきたとしても、それはコードの変更である前にライセンスの判断になります。

`avatars/` と `public/models/` の中身は、このリポジトリのライセンスの対象外です。チェックアウトして手に入るのはランタイムであって、それが動かすキャラクターではありません。

テストは GLB を読まず、コード上で合成のアバターを組み立てます。購入した 16 MB のモデルを必要とするテストは、それを買ったマシンでしか走らないためです。フィクスチャを足すのではなく `tests/helpers/scene.ts` を拡張してください。
