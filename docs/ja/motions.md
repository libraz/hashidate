# モーション

同梱のジェスチャの隣に、自分で書いた動きを足すためのものです。

`show/motions/` に YAML を 1 枚置くと、それがファイル名そのままの id を持つジェスチャになります。`gesture` で再生でき、行から名前で呼べ、語彙一覧にも組み込みのものと並んで出てきます。`--motions <dir>` でディレクトリごと移せます。中身は git 管理外です。

```sh
yarn ctl motions             # サーバから見えているもの
yarn ctl gesture salute      # 再生
```

レンダラは接続したときにディレクトリを読みます。編集のループは、ファイルを直してページを再読み込みする形になります。

## キーフレーム方式

組み込みのジェスチャは時間の関数です。`wave` は振幅が減衰する正弦波です。一定の振幅で 3 秒振り続ける手は、挨拶ではなくメトロノームに見えるためです。`nod` は減衰振動です。1 回だけの動きはただの痙攣に見え、2 回目の小さいほうがうなずきに見せているためです。この種の数値は誰かがファイルに打ち込むものではありません。レンダリングを見ながら詰めたもので、`src/engine/motion/gestures/` の各数値の横には、それが何の失敗を防ぐために存在するのかが書いてあります。

そのためこちらの形式は、ある時刻のポーズを並べて間を補間するものです。テキストエディタで人間が実際に制御できるのはこちらです。組み込みの形式より表現力は低く、それは意図したことです。ジェスチャ表をこちらへ移す予定はありません。キーフレーム化した `nod` は、チューニングを抜いた `nod` になります。

同じ理由から 2 つの帰結があります。

**ジェスチャ表にすでにある名前は拒否されます**。上書きはしません。プリセット表が名前で呼んでいるものは、呼んだとおりのままでなければならないためです。そうでないと、このランタイム向けに書いた台本が別の機械では違う動きをします。

**アイドルの自動再生は選びません**。あちらは誰も頼んでいないジェスチャを出すので、レンダリングで確認済みの集合からしか引けません。読み込んだモーションは、名指しされたときに再生されます。

## ファイル形式

```yaml
label: { en: Salute, ja: 敬礼 }
group: greeting
lead: 0.3
hold: 1.4

frames:
  - at: 0
    arms:
      R:
        upperArm: [0.30, -0.90, 0.10]
        lowerArm: [0.17, -0.95, 0.26]
        hand:     [0.13, -0.96, 0.24]
    fingers:
      R: { thumb: 0.2, index: 0.1, middle: 0.1, ring: 0.12, little: 0.16 }

  - at: 0.45
    arms:
      R:
        upperArm: [0.46, -0.42, 0.32]
        lowerArm: [0.10, 0.86, 0.50]
        hand:     [0.05, 0.72, 0.69]
        palm:     [-0.10, 0.30, -0.95]
        twist: 0.2
    spine:
      head:  [0.03, 0, 0]
      chest: [0.02, 0, 0]
```

| 項目 | 中身 |
|---|---|
| `label` | 両言語。エンジン内でユーザーに見えるものはすべてそうです。 |
| `group` | `reaction`、`greeting`、`explain`、`emote`、`cute`、`pose`、`affection`、`playful`、`idol`、`cheer`、`dance`、`photo` のどれか。 |
| `lead` | 入りの秒数。下限です。実際の入りは腕が動く距離に応じて伸びます。 |
| `hold` | 全開のまま保つ秒数。この後に抜けが始まります。 |
| `sustain` | 自然に終わらせず、次の指示が来るまでポーズを保ちます。 |
| `loop` | 最後のフレームで落ち着かせず、頭から繰り返します。 |
| `frames` | 開始からの秒数 `at` を昇順に並べたポーズ。 |

### 位置ではなく向き

`arms` は肩から手までの 4 リンクを**キャラクター空間**の向きで書きます。x が正中線から外向き、y が上、z が前です。方向ベクトルは少なくとも 1 成分を 0 以外にしてください。補間前に正規化されるので、長さは関係なく向きだけが効きます。`palm` は手のひらがどちらを向くかを指定します。手を向けるだけでは指の向く先しか決まらず、その軸まわりの回転は書かなければ成り行きで決まるため、指定する価値があります。

`fingers` は指ごとの曲がりで、0 がまっすぐ、1 が握り込みです。`spine` はスロットごとのラジアンでの加算オフセットで、`hips`、`spine`、`chest`、`neck`、`head` があります。

左右は書き分けます。組み込みの表は 1 つのポーズを書いて空いているほうの手へ鏡像化しますが、それができるのは全項目を両手で確認してあるからです。ファイルは `L` か `R` を書いて、書いたほうになります。

### 省略した項目は 0 ではなく未指定

腕の各方向、手のひらの方向、ひねり、指の曲がり、脊柱の各スロットを、それぞれ独立したキーフレームとして扱います。その項目を指定した前後のフレーム間で補間し、省略されたフレームでは値を初期化しません。最初の指定より前と最後の指定より後は、その端の値を保ちます。1 度だけ指定した項目はモーション全体で一定なので、腕を 4 フレーム動かしながら脊柱を 1 度だけ指定できます。

### この形式が扱わないもの

`reach` と `point` です。この 2 つは組み込みの表が特定アバターの実測プロポーションに対して解いているもので、外した reach は、だいたい合っているようには見えません。手が顔にめり込みます。ジェスチャ表にはそれを書けるようにする注記がありますが、ディレクトリに置いたファイルにはありません。向きを間違えたときの代償は変な角度の腕で、これは見えるので直せます。

## ばらつき

同じジェスチャでも 2 回が同一にならないよう、少しばらつきが加わります。キーフレーム列に対しては次のように働きます。

- `rate` は**時間**を伸縮します。キーフレーム列にとって「速く」と言えるのはこれだけです。
- `scale` が届くのは**背骨**だけです。向きに振幅はなく、向きを定数倍すれば別の方向を指すだけで、同じポーズを小さくやったことにはなりません。
- `side` は**何もしません**。組み込みの表は 1 つのポーズを書いて空いているほうの手に鏡映しますが、そうできるのはどのエントリも両手で確認してあるからです。ファイルは `L` か `R` を自分で書いてそのとおりになるので、読み込んだモーションへの `--side` は、誰も確認していない反転をするのではなく無視されます。

## 解析エラー

読めなかったファイルは、捨てるのではなく理由付きで一覧に出ます。ただ出てこないだけだと、ファイル名を打ち間違えたように見えるためです。

```
$ yarn ctl motions
  salute           Salute           [greeting] 2f
  broken           group: invalid option
```

ファイル名が使える id でない場合（64 文字を超える、または制御文字を含む）も、ファイル名のまま同じように一覧に出ます。壊れたモーションが 1 つあっても、ほかのモーションは隠れません。

`loop` の最初と最後のキーフレームが違うと、1 周ごとに飛びます。これは検査していません。どこまで近ければ十分かは、レンダリングを見て決めることだからです。
