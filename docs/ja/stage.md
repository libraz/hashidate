# ステージ

キャラクターが**見えている**部屋です。声が聞こえる部屋とは別の軸で、意図的に連動させていません。

## 背景

`dusk` / `night` / `morning` / `rain` の 4 つですが、4 つの部屋ではなく 1 つの部屋を 4 通りに照らしたものです。躯体も窓も家具の大半も共有していて、違うのは光がどこから来るか、その色温度、そして画面のどこに最も明るい値と最も暗い値が落ちるかだけです。背景は顔の後ろで 2 時間もたなければならないので、配色ではなく明度の構造で組んでいます。

部屋の躯体、照明、表面（漆喰、フローリング、織りの布、窓の外）は、起動時にコードから手続き的に生成します。ビューアはローカルにある家具の GLB も読み込めます。対象は `gothic-bed.glb`、`gothic-commode.glb`、`sofa.glb`、`pillows.glb` の 4 つです。これらは git の管理対象外で、新しいチェックアウトには存在しないため、家具は実行時に任意で用意するデータです。

指定は URL です。OBS のブラウザソースに渡すのはこのアドレスそのものです。

```
http://127.0.0.1:8765/?size=1920x1080&backdrop=night
```

動かし方は[OBS から使う](getting-started.md#obs-から使う)と同じです。`:8765` は `yarn build` と `yarn start`（または `yarn shell`）が要り、`make dev` では `:5173` を使います。

知らない名前はエラーではなく素の背景になります。URL はエラーの報告先がないフィールドに打ち込まれるものだからです。配信の途中で変えるためのコマンドでもあります。

```sh
yarn ctl backdrop dusk
yarn ctl backdrop        # 素の背景
```

部屋は絵の仕上げも持っています。キャラクターより奥にあるものは深度に応じてぼかし、ぼけはキャラクターの奥側の端を少し越えたところから始まります。家具は遠のき、髪や手はシャープなままです。そのうえで、部屋ごとの値で色調を整え、四隅を落とします。これをかけるのは部屋だけです。単色の背景、透過のソース、後ろにスライドがある場合はかけません。そこから先の合成は外側の仕事だからです。Bloom が OFF なら、ポストプロセス自体を通しません。

## ゲーム画面の上に重ねる

背景を選ばないと、キャラクターは単色の上に立ちます。これは意匠ではなく最低水準で、ブラウザで開いただけのページは、後ろに何か塗らなければ市松模様になるためです。ただ、ゲームのキャプチャの上ではその単色が邪魔になります。配信の主題を覆う不透明な矩形だからです。

`?transparent=1` でそれを外します。あとの合成は OBS の仕事です。

```
http://127.0.0.1:8765/?transparent=1&place=bottom-right:0.32x0.6
```

動かし方は[OBS から使う](getting-started.md#obs-から使う)と同じです。`:8765` は `yarn build` と `yarn start`（または `yarn shell`）が要り、`make dev` では `:5173` を使います。

下にゲームキャプチャかウィンドウキャプチャ、上にこの URL のブラウザソースを置くと、キャラクターがその上に乗ります。`place` の挙動はスライドの前に立たせるときと同じで、ショットは動かさず、その絵を小さくするだけです。空いた側はフレームの外へ出して切り落とします。

背景を選べばそちらが勝ちます。部屋は自前の背景を持つ不透明な形状で、透過を入れたまま部屋を選ぶのは、部屋を出すよう指示していることになるためです。

透過は URL に置いてあり、意図的にコマンドにしていません。下に何があるかはソースを置いた OBS のシーンの性質で、台本の 1 行に知りようがないからです。ゲーム画面をこのページの**中に**取り込む方法は、肝心の場所で動きません。OBS に埋め込まれたブラウザには画面キャプチャの許可を出す方法がなく、素のブラウザウィンドウでしか動かないうえ、ゲームの全フレームを 2 度取ることになります。

## フレームのどこに立たせるか

```sh
yarn ctl place avatar --anchor bottom-right --width 0.32 --height 0.6
```

小さくなるのは**絵**であって、ショットではありません。カメラは動かないので、画角に合わせて作ったジェスチャはそのまま同じように再生されます。

矩形は**場所**であって、ショットを決めるものではありません。画角はワールド空間の上端と下端で定義してあるので、別の形の矩形に向けると必ず何かを捨てることになり、思いつく 2 つの答えはどちらも誤りです。

- 矩形を埋めれば上下は保たれて、腕が両側から切り落とされます。上げた手も髪の大半もそこにあります。
- 横が収まるまでカメラを引けば何も切れませんが、上下も同じ倍率で広がるので、上半身のショットが黙って全身になります。

そこで描くのは画面そのものの形で、それを場所の中に収まる大きさへ縮めます。画面いっぱいなら映っていたはずの絵が、小さく、端に寄って出ます。場所のうち絵が覆わない部分は透明なので、そこには後ろのスライドが見えます。

端に着くのは、その絵ではなく**キャラクター自身**です。画角は横に広い絵で、その真ん中に細い人が立っているので、絵の端を画面の端に合わせるとキャラクターは端から画面 1/4 ほど手前で止まり、広い空白の前に立つことになります。空いている側は端の外へ押し出して、そこで切ります。

つまりキャラクターについては、2 つの比のうち小さいほうしか効きません。1 のままなら寄せ先がありません。2 つの比が本当に要るのはスライドのほうで、そちらには `fit` があります。[スライド](slides.md)を参照してください。

置き方は行にも載ります。`stage.place` です。台本が資料のためにキャラクターを退かせて、あとで戻すのはこれです。

```yaml
- text: "[present]資料を出すこともできます。"
  stage:
    deck: hashidate
    slide: 1
    place:
      avatar: { anchor: bottom-right, width: 0.26, height: 0.54, margin: 0.015 }
```

同じ行に載せるのは意図的です。別のコマンドとして送ると置き方は別の瞬間に着地し、いま話しているページの真ん中にキャラクターが立つという、いちばん目立つ形でフレームが一瞬狂います。[台本](scripts.md)を参照してください。

## キャラクターを隠す、絵の中で左右にずらす

```sh
yarn ctl place avatar --hide        # 声だけにする
yarn ctl place avatar --show
yarn ctl place avatar --shift=-0.2  # 絵の幅の 2 割ぶん左へ
```

`visible: false` で止まるのは、キャラクターを描くことだけです。モデルは読み込まれたままで、その裏のセッションは見えないところで話し、動き、口を動かし続けます。だから声だけで話す区間も時間はそのままで、もう一度出すとジェスチャの途中から戻ります。部屋も出たままです。台本をキャラクターなしで始めて、あとから出すときもこれを使います。

`shift` は、人物を自分の絵の中で左右にずらします。単位は絵の幅に対する割合で、−0.5〜0.5、正の値で右へ動きます。レンズシフトなので、カメラは動きも回りもしません。画角もジェスチャも変わらず、画面いっぱいの絵は画面を覆ったままです。画面いっぱいのキャラクターを中央から外して立たせたいとき、寄せ先のない立ち位置の代わりに使うのがこれです。隅に置いた絵は、人物が画面の端に立つところまですでに寄せてあります。そこからさらに同じ端へずらすと、人物が画面の外に出ます。

どちらも配置のキャラクター側の項目なので、配置を書ける所ならどこでも書けます。パネルのスライドのタブ、行の `stage.place`、行の途中の `[@place {JSON}]` キューです。

```yaml
- text: "ここからしばらく、声だけで話します。"
  stage:
    place:
      avatar: { visible: false }
- text: '[@place {"avatar":{"visible":true,"shift":-0.2}}]お待たせしました。'
```

台本を途中から始めたときも、ほかの配置と同じく、この 2 つを引き継ぎます。また、どちらも設定した台本が終わったあとまで残ります。キャラクターを隠した台本は、終わる前にもう一度出してください。出さないと、次の台本はキャラクターなしで始まります。

## Bloom

Bloom は描画したシーンの明るい部分を柔らかくにじませます。初期状態は OFF です。パネルまたはビューアーの調整タブで **ブルームを有効にする** を ON にし、強さ・広がり・明るさのしきい値を調整します。しきい値を下げると画面のより広い部分が対象になり、強くかけると白い服や肌もにじみます。

```sh
yarn ctl bloom on
yarn ctl bloom on --strength 0.2 --radius 0.4 --threshold 0.85
yarn ctl bloom off
```

API も同じ設定を部分指定で受け取ります。

```json
{"cmd":"bloom","enabled":true,"strength":0.2,"radius":0.4,"threshold":0.85}
```

`strength` は 0..3、`radius` は 0..1、`threshold` は 0..2 です。省略した値は維持し、OFF にしても次回用のパラメーターは残ります。プレビューとステージで設定を共有し、アバターの切り替えや後から接続したレンダラーにも引き継ぎます。録画には描画済みのキャンバスから効果を取り込みます。スライドの資料は別レイヤーなので、にじみません。

MCP では `stage` に `{"bloom":true}` または `{"bloom":false}` を渡します。台本では各行の `stage.bloom` で切り替えます。[台本](scripts.md#bloom)を参照してください。
