# はじめかた

## 必要なもの

クローンして手に入るのはランタイムだけです。必要なもののうち 2 つは意図的に同梱していないので、最初の `yarn install` の前にここを読んでください。

### とにかく動かすために

| 必要なもの | 補足 |
|---|---|
| Node 22 と Yarn 4 | `mise.toml` で固定してあります。`mise install` で両方入ります。 |
| **アバター** | 必須で、**同梱していません**。`src/avatars` の記述子は `public/models/<id>.glb` を指していますが、この GLB は git 管理外です。そこに何も無ければ、レンダラは描くものがない状態で立ち上がります。 |

このプロジェクトが相手にしてきた 2 体は市販の VRChat 向けモデルで、再配布できるものではありません。ですから、モデルはご自身で用意してください。リグ済みのヒューマノイドモデルを `make glb` に通し、記述子を 1 ファイル `src/avatars` に置く——アバターを足す作業はそれで全部です。[アバター](avatars.md)を参照してください。

### 声を出すために

| 必要なもの | 補足 |
|---|---|
| `uv` と Python 3.11 | サイドカーの環境をこれらから作ります。PyTorch が入るので、それだけで数 GB になります。 |
| **参照音声** | 声には必須で、**同梱していません**。サイドカーは録音から声を複製しますが、このプロジェクトが使っているのは実在する人物の録音で、どんな形であれ公開できるものではありません。 |

`tools/tts/reference/clips/` に WAV を何本か置いてください。このディレクトリは、そのために空のまま同梱してあります。あとはコマンド 1 つです。

```sh
make voice
```

Python 環境が無ければ作り、クリップを検査し、サイドカーが起動時に読む潜在表現へ変換します。クリップを足して再実行したときは、変換だけをやり直します。

条件は、雑音のない音声で、話者は 1 人、音楽も第二の声も入っていないこと。合計 1〜2 分あれば足ります。学習用データセットではなく参照だからです。`make tts-vet` は何も作らずに検査結果だけを出しますし、`make voice` は検査に落ちたクリップからは作りません。声が持つべきでない参照は、あとの設定で取り消せないからです。`HASHIDATE_VOICE_DIR` で置き場所ごと——リポジトリの外へも——移せます。

厳密にはサイドカーは任意です。無ければ、テキストから組み立てた尺で無音のまま口だけが動きます。テストが走っているのも、声を持たない環境も、この状態です。とはいえ、音の出ない VTuber はテスト用の置物なので、おまけではなく最初から見込んでおいてください。

別の音声合成のほうが合うなら、レンダラはこのサイドカーを直接呼んではいないので差し替えられます。同じポートで `POST /speak` に `{ text, reading? }` を受けて WAV を返し、`GET /health` に答えるものなら何でも代わりになります。[音声](speech.md#別の声を使う)を参照してください。

### 要るときだけ

| ツール | いつ要るか |
|---|---|
| Blender | 購入した、あるいは自作したモデルを GLB に変換するときだけ。動かすだけなら要りません。 |
| OBS | 結果を配信に乗せるときだけ。レンダラはただのページです。 |

## 動かす

```sh
yarn install
make dev
```

`make dev` はビューアを `127.0.0.1:5173` に、制御 API を `127.0.0.1:8765` に、音声サイドカーを UNIX ソケットに立て、前者の `/api` を後者へ中継します。音声はその環境が作られていなければ外れます。普通はそちらです。`yarn dev` なら前の 2 つだけを立てます。

Ctrl-C で 3 つとも止まります。その機会がなかったとき——ターミナルを閉じた、接続が切れた——古いプロセスが 2 つのポートとソケットを掴んだままになり、次の `make dev` は bind に失敗します。`make stop` がそれを解放します。何かを覚えておくのではなくアドレスを見るので、どのプロジェクトが残したリスナーでも片付きますし、止める前にその 1 つずつを表示します。停止ではなく kill されたサイドカーが残したソケットファイルも消します。中身の無いそれへの bind は、本物の衝突とまったく同じように失敗するからです。

別のターミナルから動かします。

```sh
yarn ctl vocab                                  # このアバターに何を頼めるか
yarn ctl perform happy                          # 表情とモーションをひと組にしたもの
yarn ctl say "こんばんは" --perform hello --wait
yarn ctl say "[hello]こんばんは。[explain]今日はこの話をします。"
yarn ctl bgm list                              # show/bgm/ の MP3 と FLAC
yarn ctl bgm play opening.mp3 --volume 0.2
yarn ctl perform                                # 解除する
yarn ctl point 40 25 --extent 0.9 --finger little
yarn ctl idle on
yarn ctl watch                                  # 発話のイベントを追う
```

区間ごとまとめて渡すこともできます。`show/scripts/demo.yaml` は、ランタイムが自分自身を 2 分ほどで紹介する台本です。ターンが実際どういうものかを見るにはこれが一番早道です。

```sh
yarn ctl play demo --check      # 読むだけ。サーバは要りません
yarn ctl play demo --replace    # 流す
```

[台本](scripts.md)を参照してください。

BGM は任意で、取り込み作業は要りません。`.mp3` または `.flac` を `show/bgm/` の直下に置くと、パネル・CLI・MCP から一覧を読むたびに再走査されます。中身は git 管理外です。[BGM](bgm.md)を参照してください。

`yarn build` は `dist/` に静的なビューアを吐きます。`yarn start` は vite を介さず、制御サーバ単体でそれを配信します。

`yarn shell` はその両方をやったうえで、パネルとステージをネイティブのウィンドウで開きます。制御サーバと音声サイドカーもその下で起動し、終了時に一緒に落とします。開いているのは同じループバックアドレスの同じ 3 ページで、足しているのは、ウィンドウが前回の位置に戻ること、クリックしなくてもステージが音を出しはじめること、この機械が声を聞くかどうかをメニュー 1 つで決められることだけです。[操作面](surfaces.md)を参照してください。

## 声を出す

実際に音を出すには、`tools/tts/reference/clips/` にクリップを置いて `make voice` を一度走らせます（[必要なもの](#声を出すために)を参照）。あとは `make dev` が他と一緒に声も立ち上げますし、`make tts` なら単体で走らせられます。本当の意味で任意です。無ければ、テキストから組み立てた尺で無音のまま口だけが動きます。テストが走っているのもこの状態です。[音声](speech.md)を参照してください。

制御サーバは起動時に音声の状態を 1 行出し、それが変わればまた出します。パネルにも同じ警告が出ます。配信の途中で応答しなくなったサイドカーは、それ以外の形では見えません。キューは流れ、口も動くからです。

## OBS を向ける

レンダラは `/` です。開くとキャラクターだけが出ます。コンソールも HUD もカーソルもありません。ブラウザソースに渡すのはこの URL です。

```
http://127.0.0.1:8765/?size=1920x1080&backdrop=night
```

`?transparent=1` を足すと背景が消え、ゲームキャプチャの上への合成を OBS に任せられます。[ステージ](stage.md)を参照してください。

このアドレスはパネルのタブの上で組み立てられます。サイズ・背景・資料・キャラクターの立ち位置を選んで、出てきたものをコピーするだけです。

自分で見るなら `/monitor/` を開きます。同じレンダラを 16:9 にレターボックスして、周りに何も置かないページです。こちらは聞くためのものです。ブラウザソースの音は配信へ流れて卓には返らないので、ふつうの構成では部屋でキャラクターの声を聞く唯一の手段になります。

## 検査を走らせる

```sh
yarn typecheck
yarn lint          # biome
yarn test          # vitest
```

テストは GLB を読まず、コード上で合成のアバターを組み立てます。購入した 16 MB のモデルを必要とするテストは、それを買ったマシンでしか走りません。`tests/helpers/scene.ts` を参照してください。

`src/engine` の数値は、実際のアバター 2 体を見ながら決めたものです。その多くには、何を防ぐために存在するのかを書いたコメントが付いています。整理のついでに丸めてよい既定値ではなく、変えるならレンダリングを見て判断することになります。
