# 録画

合成された画をそのまま動画ファイルに書き出す。書き込むのは制御サーバー。

配信そのものは OBS でやればいい。ここが引き受けるのはそうでないほう——台本で一本撮る、資料を後ろに置いて、一度だけ。そのためにコンポジタを立ち上げてブラウザソースの URL を貼って正しいボタンを押すのを忘れない、というのは仕事量に見合わない。

## 手順

1. **台本を読み込む。** キュータブの、キューのすぐ上に `show/scripts/` の中身が並ぶ。押すとキューを置き換えて読み込み、そして喋り出さない。行はその下にそのまま出るので、効いたことが分かる。
2. **画角を決める。** キャラクターは台本を丸ごと抱えたまま立っている。プレビューをドラッグし、資料の位置を決め、部屋を選ぶ。
3. **録画タブで録画を押す。** 録画が始まり、実際に書き込みが始まった時点でキューが解放される。
4. **最終行の少しあとで勝手に止まり**、ファイルが `show/recordings/` に落ちている。

1 が効いているから残りが成立する。読み込んだ瞬間に喋り出す台本だと、最初の 2 行のあいだに画角を決めるか、決め打ちで読み込んで祈るかしかない。

止めているのは一覧の隣の**「読み込んだら止めておく」**。既定はオン、録画に要るのがこれだから。オフにすれば一覧は見たとおりのものになる——台本を押せば再生される。プロンプトから `yarn ctl play` を打ったときと同じで、その場で流したいときはこちら。

一時停止そのものは発話中の表示のところにある。**再生開始**と**一時停止**。そこが置き場所として正しい——20 行を抱えて止まっているキューと、何も無くて空いているキューは、「いま何か起きているか」への別々の答えで、あの表示はその問いだから。

## 停止中でも準備は進んでいる

止まっているのはキューの進行だけで、音声合成は進んでいる。行の音声は再生時ではなく**キューに入った時点**で作られるので、画角を決めているあいだに音声合成サイドカーは台本を頭から処理している。解放した瞬間に一行目が出るのはそのため——そうでなければ、一行目の合成を待つ 1 秒あまりが録画の頭に入る。

解放をタイマーではなく**証拠**でやっているのも同じ理由。パネルは「録画開始」を送ってから一拍おいて「再生」を送るのではなく、サーバーが録画コマンドを配り、エンコードされた最初のチャンクが返ってきてから初めてキューを解放する。エンコーダーが最初のフレームを吐くまでの時間を見積もれば短すぎる場合があり、少しでも短ければ録画の頭で一行目の出だしが切れる。

一時停止はふつうのコマンドなので、単体でも使える。

```sh
yarn ctl play opening --hold   # 読み込むが再生しない
yarn ctl resume                # 解放する
yarn ctl hold                  # また止める
```

一時停止が届いた時点で喋っている行は最後まで喋る。何も捨てない——途中で切るのは `interrupt`、残りを捨てるのは `clear`。

## 出力サイズはウィンドウのサイズではない

画は指定されたサイズのキャンバスにもう一度組み直される。ステージウィンドウが全画面だろうと机の端の細い帯だろうと、録画は 1920×1080 になる。

組み直しが必要なのは、画面上のものが 1 枚のキャンバスではないから。資料の層は DOM のキャンバスで、ブラウザがそれを WebGL キャンバスの**背後に**合成し、さらにその後ろは CSS になっている。どちらか一方をキャプチャしても、画の半分が欠けた録画にしかならない。

できないのは解像度を増やすこと。幅 800 で描かれているステージウィンドウを幅 1920 の録画に引き伸ばせば眠い絵になる。ぼやけるならステージウィンドウを大きくする。

## 録画するのは一つだけ、音を出しているほう

録画コマンドは接続中のすべてのレンダラーに届き、ふつうの机の上でそれは最低 2 つある——ステージと、パネルのプレビュー。実行するのはミュートされていないほうだけ。

これはミュートがすでに引いている線をそのまま使っているだけで、別の規則ではない。モニターとは音を出さないページのことで、録画に入るべきものは部屋が聞いたものだから。したがって、OBS がブラウザソースを監視しているためにミュートしてあるステージは録画しない——そしてそれでいい。そのときは OBS が録っている。

声と処理済みの BGM は、このミュートと録画への分岐より前で合流します。そのため、音を出しているレンダラが作る録画には、ページから聞こえた音量のまま両方が入り、BGM 専用の libsonare エフェクトも反映されます。[BGM](bgm.md)を参照してください。

## mp4、あるいは中身どおりの名前

エンコードはブラウザ側でやっていて、まず MP4 を要求する——`avc1` 映像に AAC 音声。どこでも開けるし、変換を挟まずに編集ソフトに放り込める。

H.264 エンコーダーを持たないビルドでは WebM に落ち、ファイル名も `.webm` になる。WebM のストリームに `.mp4` と名前を付けるのは、どちらよりも悪い唯一の結末——開けないファイルに、嘘の名前が付く。

拡張子は要求した形式ではなくエンコーダーが実際に選んだ形式で決まる。だから最初のチャンクが届くまでファイルには名前がない。どのレンダラーも実行しなかった録画——接続中がすべてミュートされたモニターだった場合——は何も残さない。タイムスタンプ入りの空ファイルが残るよりましだから。

## 落ちる場所

`show/recordings/`。slides・scripts・motions と並ぶ。git 管理外なのはサイズより強い理由による——購入したアバターがクローンした声で喋っている数分の動画だから。

名前はキューの出どころの台本と、開始時刻。

```
show/recordings/opening-20260829-142530.mp4
```

`--recordings` でディレクトリを移せる。`--slides` や `--motions` と同じ扱い。ネイティブシェルには `Window → Open Recordings Folder` がある。

## 停止

最終行の少しあとで終わる。口が閉じてキャラクターが休めの姿勢に戻るだけの間はある——最後の音節と同じフレームで切れると、接続が落ちたように見えるから。その間に行がキューに入れば録画は止まらずに続く。

**台本の終わりで停止**を切れば、停止ボタンを押すまで回り続ける。

どちらにせよ、停止のあと 1 秒ほどファイルは開いたままになる。エンコーダーは巻き取りを指示された時点でまだフレームを抱えていて、最後のチャンクではなくコマンドで閉じると、どの録画もちょうどその分だけ尻切れになる。書き込み済みバイト数が終わったかどうかを教えてくれる——それはディスクに実際に落ちた量で、まだ動いているレコーダーと黙って止まったレコーダーを見分けられる唯一の数字。
