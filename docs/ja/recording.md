# 録画

合成された画をそのまま動画ファイルに書き出す機能です。ファイルを書くのは制御サーバです。

配信そのものは OBS でやれば足ります。ここが引き受けるのはそうでないほう、つまり台本で一本だけ撮るときです。スライドを後ろに置いて、一度だけ録ります。そのためにコンポジタを立ち上げ、ブラウザソースの URL を貼り、正しいボタンを押すのを忘れないでいる、というのは仕事量に見合いません。

## 手順

1. **台本を読み込みます。** キュータブでは、キューのすぐ上に `show/scripts/` の中身が並びます。押すとキューを置き換えて読み込み、そして喋り出しません。行がその下にそのまま出るので、効いたことが分かります。
2. **画角を決めます。** キャラクターは台本を丸ごと抱えたまま立っています。プレビューをドラッグし、スライドの位置を決め、部屋を選びます。
3. **録画タブで録画を押します。** 録画が始まり、実際に書き込みが始まった時点でキューが解放されます。
4. **最終行の少しあとで勝手に止まり**、ファイルが `show/recordings/` に落ちています。

1 が効いているから残りが成立します。読み込んだ瞬間に喋り出す台本だと、最初の 2 行のあいだに画角を決めるか、決め打ちで読み込んで祈るかしかありません。

止めているのは一覧の隣の「**読み込んだら止めておく**」です。既定はオンで、録画に要るのがこちらだからです。オフにすれば一覧は見たとおりのものになります。台本を押せば再生される、という状態です。プロンプトから `yarn ctl play` を打ったときと同じなので、その場で流したいときはこちらを使ってください。

一時停止そのものは発話中の表示のところにあります。**再生開始**と**一時停止**です。そこが置き場所として正しいと考えています。20 行を抱えて止まっているキューと、何も無くて空いているキューは、「いま何か起きているか」への別々の答えであり、あの表示はその問いだからです。

## 停止中でも準備は進んでいます

止まっているのはキューの進行だけで、音声合成は進んでいます。行の音声は再生時ではなく**キューに入った時点**で作られるので、画角を決めているあいだに、音声合成サイドカーは台本を頭から処理しています。解放した瞬間に一行目が出るのはそのためです。そうでなければ、一行目の合成を待つ 1 秒あまりが録画の頭に入ってしまいます。

解放をタイマーではなく**証拠**で行っているのも同じ理由です。パネルは「録画開始」を送ってから一拍おいて「再生」を送るのではありません。サーバが録画コマンドを配り、エンコードされた最初のチャンクが返ってきてから初めてキューを解放します。エンコーダが最初のフレームを吐くまでの時間は、見積もれば短すぎる場合があり、少しでも短ければ録画の頭で一行目の出だしが切れます。

一時停止はふつうのコマンドなので、単体でも使えます。

```sh
yarn ctl play opening --hold   # 読み込むが再生しない
yarn ctl resume                # 解放する
yarn ctl hold                  # また止める
```

`hold` と `resume` は、ワイヤ上では 1 つのコマンド `pause` の両面です。CLI で 2 つに分けてあるのは、状態を 2 つ持つフラグが、録画の頭で取り違えやすいものを 1 つ増やすからです。[コマンド](commands.md)を参照してください。

一時停止が届いた時点で喋っている行は、最後まで喋ります。何も捨てません。途中で切るのは `interrupt`、残りを捨てるのは `clear` です。

## 出力サイズはウィンドウのサイズではありません

画は、指定されたサイズのキャンバスにもう一度組み直されます。ステージウィンドウが全画面だろうと机の端の細い帯だろうと、録画は 1920×1080 になります。

組み直しが必要なのは、画面上のものが 1 枚のキャンバスではないからです。スライドの層は DOM のキャンバスで、ブラウザがそれを WebGL キャンバスの**背後に**合成し、さらにその後ろは CSS になっています。どちらか一方をキャプチャしても、画の半分が欠けた録画にしかなりません。

できないのは解像度を増やすことです。幅 800 で描かれているステージウィンドウを幅 1920 の録画に引き伸ばせば、眠い絵になります。ぼやけるなら、ステージウィンドウを大きくしてください。

## 録画するのは 1 つだけ、音を出しているほうです

録画コマンドは接続中のすべてのレンダラに届き、ふつうの机の上でそれは最低 2 つあります。ステージと、パネルのプレビューです。実行するのは、ミュートされていないほうだけです。

これはミュートがすでに引いている線をそのまま使っているだけで、別の規則ではありません。モニタとは音を出さないページのことであり、録画に入るべきものは部屋が聞いたものだからです。したがって、OBS がブラウザソースを監視しているためにミュートしてあるステージは録画しません。そしてそれで正しいのです。そのときは OBS が録っています。

声と処理済みの BGM は、このミュートと録画への分岐より前で合流します。そのため、音を出しているレンダラが作る録画には、ページから聞こえた音量のまま両方が入り、BGM 専用の libsonare エフェクトも反映されます。[BGM](bgm.md)を参照してください。

## mp4、あるいは中身どおりの名前

エンコードはブラウザ側で行っており、まず MP4 を要求します。`avc1` 映像に AAC 音声です。どこでも開けますし、変換を挟まずに編集ソフトへ放り込めます。

H.264 エンコーダを持たないビルドでは WebM に落ち、ファイル名も `.webm` になります。WebM のストリームに `.mp4` と名前を付けるのは、どちらよりも悪い唯一の結末だからです。開けないファイルに、嘘の名前が付くことになります。

拡張子は、要求した形式ではなくエンコーダが実際に選んだ形式で決まります。だから、最初のチャンクが届くまでファイルには名前がありません。どのレンダラも実行しなかった録画——接続中がすべてミュートされたモニタだった場合——は、何も残しません。タイムスタンプ入りの空ファイルが残るよりましだからです。

## 落ちる場所

`show/recordings/` です。slides・scripts・motions と並びます。git 管理外にしているのはサイズより強い理由によります。購入したアバターが、クローンした声で喋っている数分の動画だからです。

名前は、キューの出どころの台本と、開始時刻です。

```
show/recordings/opening-20260829-142530.mp4
```

`--recordings` でディレクトリを移せます。`--slides` や `--motions` と同じ扱いです。ネイティブシェルには `Window → Open Recordings Folder` があります。[ネイティブシェル](shell.md)を参照してください。

## 停止

最終行の少しあとで終わります。口が閉じてキャラクターが休めの姿勢に戻るだけの間はあります。最後の音節と同じフレームで切れると、接続が落ちたように見えるからです。その間に行がキューへ入れば、録画は止まらずに続きます。

**台本の終わりで停止**を切れば、停止ボタンを押すまで回り続けます。

どちらにせよ、停止のあと 1 秒ほどファイルは開いたままです。エンコーダは巻き取りを指示された時点でまだフレームを抱えており、最後のチャンクではなくコマンドで閉じると、どの録画もちょうどその分だけ尻切れになります。終わったかどうかを教えてくれるのは、書き込み済みバイト数です。これはディスクに実際に落ちた量であり、まだ動いているレコーダと黙って止まったレコーダを見分けられる唯一の数字です。

## 出てくるのは可変フレームレートです

録画のフレームは、合成用のキャンバスが描き替わったときに 1 枚できます。描き替えの上限は画面のリフレッシュレートで、ブラウザはそれより速く描けません。だから 60 fps を頼んでも、50 Hz のディスプレイに映っているレンダラは 50 fps しか出しません。

エンコーダは実際に描かれた時刻をそのまま打つので、出来上がりは、平均 49.36 fps といった半端な値を持つ可変フレームレートのファイルになります。**中身は正しいものです。** 音声パケットの間隔も、映像フレームの間隔も、両ストリームの開始時刻も揃っていて、口の動きと声は端から端まで合っています。

ずれるのは、これを固定フレームレートとして読む再生・編集環境に渡したときだけです。実データが 50 fps しかないものを 60 fps のつもりで並べれば、映像の進みが変わり、音だけが先に行っているように聞こえます。ファイルの側は何も壊れていないので、測っても原因が出てきません。`ffprobe` が返す `avg_frame_rate` の半端な分数が、その印になります。

## 録ったあとに一度通します

固定フレームレートに直せば、このずれは消えます。値は録画時のリフレッシュレートに合わせてください。

```sh
ffmpeg -i show/recordings/<take>.mp4 \
  -fps_mode cfr -r 50 -c:v libx264 -preset veryfast -crf 18 -c:a copy \
  show/recordings/<take>-cfr50.mp4
```

音声は再エンコードしません。触る理由がありませんし、声はこのランタイムがいちばん失いたくないものだからです。

ファイルはたいてい大幅に小さくなります。18 分のスライド解説で、615 MB が 147 MB になった例があります。品質を落としたわけではありません。ブラウザのエンコーダは配信しながら符号化していて先読みも B フレームも使えないぶん、動いていない時間にもビットを払い続けています。スライドが止まっている画では、その差が大きく出ます。

ディスプレイを 60 Hz にできるなら、そちらは変換なしで済む根本の答えになります。ただし、ずれを消すだけならこの後工程で足ります。
